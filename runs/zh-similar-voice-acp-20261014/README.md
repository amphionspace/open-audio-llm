## 训练

起点 Emilia2 轮 6000 步。10% 原版权重插值（weight-interp-20261014）在选模面板上更好（AliMeeting dev 20.34），但在最终面板上变差（合成中文会议 10.2 → 18.1、AISHELL-5 dev 27.8 → 30.4、AliMeeting test 21.1 → 21.6），因此不作为起点，选中的 checkpoint 也不再做插值。

其余与前两轮相同：全局 batch 32，学习率 5e-6、500 步 warmup 后 cosine 至 12000 步，每 1000 步保存，新优化器。

## 判定

- 目标：AliMeeting dev 不计复读 cpER 最低。
- 门槛不变：6–12 人合成不升 5 点、WenetSpeech/KeSpeech dev 各不升 1 点、复读不超过起点 + 6。
- 验收（对起点，AliMeeting dev）：高相似 1/3 窗口的说话人归错（>3 字句子按字数汇总）≤ 2.0；cpER < 19.5；与他人重叠语句的字错不变差超过 0.5。
- 选模器加报：按说话人对齐后的字错 / 归错、高相似窗口归错、起点偏差 > 1 秒的语句占比；step 0 重新测，给这些新指标做基线。

## 结果（2026-10-16）

结论：**不采用，目标没有达成。** 10 个保存点里没有一个在 AliMeeting dev 上超过起点，高相似窗口的说话人归错反而变多；起点（Emilia2 6000 步）仍是最好的模型。

- 执行：train 001 在约 10305 步按停止文件正常结束（ACP `pt-a9cu9diz` SUCCEEDED）。选模 001 在 7000 步评测时失败：GPU 3 被他人占用，空闲只有 18 GiB，不够 vLLM 要的 23.8 GiB；002 换到 GPU 2，用 `previous_state` 接上 1000–6000 步的结果，跑到 10000 步，因 6–12 人合成连续三次超出门槛（8000/9000/10000 步：31.8 / 30.8 / 30.5，门槛 24.7 + 5）而叫停，并跑了最终面板。
- 选模（AliMeeting dev，不计复读，起点 20.63）：最低是 2000 步的 20.85，其余 21.0–22.4。

| 步数 | cpER | 高相似 1/3 窗口归错 | 起点偏差 >1 秒的语句 | 6–12 人合成 |
| --- | --- | --- | --- | --- |
| 0（起点） | 20.63 | 3.10 | 17.7% | 24.71 |
| 2000 | 20.85 | 3.51 | 17.6% | 26.53 |
| 6000 | 21.88 | 5.81 | 17.0% | 25.17 |
| 8000 | 21.79 | 5.05 | 17.0% | 31.77 |
| 10000 | 22.27 | 4.29 | 16.9% | 30.47 |

- 验收（对起点）：高相似归错 ≤ 1.55 没达到（最好 3.51）；cpER < 19.5 没达到；与他人重叠语句的字错基本不动（18.5 → 18.4–19.2）。WenetSpeech / KeSpeech dev 一直在门槛内（3.95–4.17）。
- 最终面板（2000 步 vs 起点，百分点）：中文真实会议 −0.06、英文真实会议 −0.42、合成 6–10 人 +0.27、fixed338 +0.03；CHiME-6 +22.7（复读 13 次）、AISHELL-5 dev +4.4、CS-Dialogue test +2.1，汇总未通过。
- 原因（**未查清**）：听审只支持一小部分——Emilia2 里最像两人相似度 ≥ 0.80 的窗口多数是同一个人被拆开，但这类窗口只有 2,571 个（1.6%，70 小时），去掉已排除的后新增 1,345 个（36 小时）。0.6–0.8 段多数是真两个人，所以"29% 超过 0.60 就是拆错"的说法不成立：多数是正常的相似双人，恰好是本轮想教的难例。拆错的标签最多解释归错变多的一小部分，主因没有定位。
- 听审核对（24 题，答案 `/workspace/workspace/mingdong/data/amphiondata/similar-voice-views-20261014/listen-review/speaker-split-20261015/answers.json`）：

| 相似度段 | 两个人 | 同一个人（MOSS 拆错） | 听不出 |
| --- | --- | --- | --- |
| 0.45–0.6（对照） | 3 | 2 | 1 |
| 0.6–0.7 | 5 | 1 | 0 |
| 0.7–0.8 | 6 | 0 | 0 |
| ≥ 0.8 | 1 | 5 | 0 |

0.60 的上限偏严，会误删正常的双人对话；上限应在 0.80 左右（每段只有 6 题，是方向，不是精确值）。数据目录里已生成的 0.60 排除名单（`split-cap/exclude-records.txt`）没有用于任何训练，不要直接使用。
- 没做的：没有重训验证。0.80 上限的排除名单已在数据目录 `split-cap-0.80/` 生成（可疑 2,571 个，新增剔除 1,345 个）。系列结论与是否再做一轮见 [2026-10-16 总结](../../docs/experiments/2026-10-16/README.md)。
