# ts-overlap-20261119：重叠时的目标转写

## 背景

2026-11-19 的复盘和白盒分析（`docs/experiments/2026-11-19-ts-retro-overlap/`，PR #167）发现：

- 11.17 的中文 TS 字错里，71% 是目标在说话、模型也出了字，但重叠时转写错了。
- 10 个版本在重叠 ≥ 0.9 样本上的转写错误率一直在 15.4–16.5%，任何一轮都没有改变它。
- 用户 2026-11-20 同意按复盘的建议推进：先改守门（方向 1）、测注册的影响（方向 3），同时准备干净原句老师的训练代码（方向 2）。
- 中英体验不回退优先；中文 TS 守门沿用 11.06 的 12.88 / 371 / 369。

## 结论（2026-11-21）

四组从 11.17 起的训练（03/04/07/08）都没有过守门，也都没有改善重叠转写：

| v12 | 字错率 | 误报 | 漏识 | 重叠 ≥ 0.9 转写错误（五个模型逐条配对） |
|---|---:|---:|---:|---:|
| 11.17 | 12.80 | 342 | 357 | 14.77 |
| 04 放开 LLM | 13.76 | 366 | 439 | 16.11 |
| 03 放开 LLM + 干净原句 KL | 14.16 | 365 | 406 | 16.62 |
| 08 冻结 LLM | 13.54 | 419 | 372 | 15.62 |
| 07 冻结 LLM + 音频塔表示损失 | 13.49 | 459 | 359 | 15.72 |

守门 12.88 / 371 / 369。配对表：`tasks/07-clean-feature/attempts/002/artifacts/eval/paired-v12-five-models.txt`。

1. **从 11.17 接着做 SFT，不管放不放开 LLM，都会全面退化**，包括无重叠的样本和中文普通识别。误报 + 漏识从 699 回到 771–818，与复盘里 SFT 模型的历史区间（802–894）一致。11.17 的这部分优势来自 GRPO v18 骨干，SFT 在把它还回去。
2. **两种老师信号都没有起作用。** 和各自的对照比：
   - 输出层 KL（03）学成了"拿不准就少写"；
   - 音频塔表示损失（07）让音频塔更不依赖注册，抄干扰人变多。
3. **编码器对注册的选择性**：交叉熵和输出层 KL 都推不动它（03/04/08），表示损失反而让它下降（07）。

所以"从 11.17 起做 SFT + 辅助损失"这条路不再继续。
