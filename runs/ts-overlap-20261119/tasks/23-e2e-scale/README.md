# 23 端到端加大训练量（沿用分离辅助任务）

## 要回答的问题

任务 21 和 22 的结论：
- 约 1,300 小时的端到端训练没有改善重叠转写；
- 分离辅助任务让编码器第 12 层更会预测目标掩码（误差 0.055 → 0.036），但还不够准，直接拿来处理输入也没有帮助。

同事 lx 的 thinker 用了约 1.3 万小时才在双人混音上做到 WER 5.32%。本任务把训练量扩大约 10 倍，并加强辅助监督，看重叠转写和掩码质量能否明显变好。用户 2026-11-23 认可。

## 设置

- **起点**：attempt 001 是任务 21 B 组第 8000 步；**attempt 002（正式）从 11.17 起**，全程使用终版文本，见下文。
- **辅助任务**：掩码头加在编码器第 6 层和第 12 层之后，权重 4（任务 21 是第 12 层一处、权重 2），掩码头随检查点保存。
- **训练**：全部参数，学习率 2e-5（预热 500 步，余弦衰减），3 万步，每步 64 条，约 190 万条在线生成场景，约 1 万小时音频。数据与任务 21 相同：26,585 个说话人，15% 换成别人的注册。

- **评测**：训练结束后，在同一个作业里评第 1 万、2 万、3 万步三个检查点，16 卡分片：
  - 615 条重叠样本，原混音和去掉干扰人两种输入；
  - 600 条副作用样本；
  - 用保存下来的第 12 层掩码头处理输入：验证集掩码误差，以及处理后的识别结果（[mask_probe.py](../../scripts/mask_probe.py) 设 `STEPS=0`）。
- **脚本**：[ft_e2e2.py](../../scripts/ft_e2e2.py)、[job_e2e2.sh](../../scripts/job_e2e2.sh)、[run_e2e2_smoke.sh](../../scripts/run_e2e2_smoke.sh)（单节点 4 步冒烟已通过）。

## 结论（attempt 002）

1. **（只在模拟器分布上成立，见下文交付守门）端到端训练第一次在重度重叠上取得显著改善。**第 3 万步 14.15% → 12.14%，主要来自 2 个干扰人的样本（−2.94，显著）。干净输入不变，说明改善来自分离目标人，不是识别本身变强。
2. **还没有收敛。**重叠错误率 17.72% → 14.13% → 12.14%，掩码误差 0.029 → 0.027 → 0.025，一直在降。第 1 万步先变差（学习率高峰期），后面持续变好。训练量是关键因素，与 lx 约 1.3 万小时的经验一致；任务 21 只训了约 1,300 小时，看不出效果。
3. **副作用**：不重叠场景显著变好（−3.05），轻度重叠持平，误报率 4.5% → 3.0%。
4. **掩码头本身仍不能直接用**：误差降到 0.025，但乘到输入上还是变差。分离能力在编码器内部体现，不需要显式掩码。
5. **离理想上限还远**：理想比例掩码下是 5.76%，现在 12.14%。
6. **未验证**：以上用 HF 解码，只覆盖 v12 中文模拟数据。还没有跑交付守门（中文 TS 12.88/371/369、英文 TS 误报 ≤ 655、中文普通识别 ≤ 4.39）和部署推理栈（vLLM + MTP）。训练数据只有中文 TS 场景，英文和普通识别可能退化，必须先测。

### 更正后的结论

1. **第 3 万步的重叠改善只在模拟器覆盖到的场景里成立。**
   - 615 条重叠集和 600 条副作用集，都取自模拟器能复现的场景类型。在这些类型上，改善是真的，服务栈也能复现：v12 里 enroll、floor、dom、dyn 等都变好。
   - 训练数据没覆盖的类型严重退化：真实录音、远近场、交接、短句、只有非语音的负样本。误报从 342 涨到 959，多出的误报集中在 nonspeech、real、nearfar。
   - 全量 v12 上，连重叠 ≥ 0.9 的转写也从 15.64 变差到 16.44。
2. **普通识别和英文严重遗忘。**
   - 训练数据只有中文 TS 模拟场景，全参数训了 3 万步，模型把英文忘了：英文音频输出成编造的中文句子，或者词之间不加空格。
   - 中文普通识别也从 4.39 退化到 11.52。
3. **所以前面"第一次显著改善"的说法只对模拟器分布成立。**这个检查点不能交付，方向能不能交付也还没有证明。
   - 能确定的一点：加大训练量确实能让编码器学到更好的目标人分离。
   - 要变成可交付的模型，训练数据必须同时覆盖原有的全部任务（中英普通识别、英文 TS、真实录音和各类负样本），不能只用模拟重叠数据。
4. 遗忘出在哪里，见下一节。

### 诊断结论

1. **灾难性遗忘主要出在 LLM。**换回 11.17 的 LLM 后，英文普通识别从 83.30 回到 10.61，中文普通识别从 11.52 回到 6.31，英文 TS 从 93.12 回到 16.58。
2. **重叠收益在编码器里，并且在真实评测集上成立。**全量 v12 的 4,554 条重叠 ≥ 0.9 样本上，只换编码器把字错率从 18.27 降到 15.85（相对 −13%，区间不跨 0）。这是目前所有尝试里最大的真实收益（任务 15 的 soup 只有 −0.28）。v12 总字错率 11.85，低于守门的 12.88。
3. **编码器本身也有中等程度的漂移**：
   - 误报升高：v12 342 → 545（超过门槛 371），英文 TS 655 → 1558；
   - 普通识别变差：中文 4.39 → 6.31，英文 8.06 → 10.61；
   - 轻度重叠 +2.29。
   
   原因是训练数据只有模拟的中文 TS 场景（其中 15% 换成别人的注册），没有普通识别、英文、真实录音和非语音负样本。
4. **下一轮的配方由此确定**：
   - 冻结 LLM，只训编码器；
   - 在模拟重叠场景之外，加回 11.17 原有任务的数据（中英普通识别、英文 TS、真实 TS 和各类负样本，全部用终版文本），让编码器在这些数据上保持原来的行为。
   
   目标是保住重叠收益，同时把误报和普通识别拉回门槛以内。
