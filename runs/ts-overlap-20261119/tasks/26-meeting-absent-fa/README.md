# 26 真实会议里目标人没说话也输出（下游反馈诊断）

## 输入

- **下游反馈包**：`anfeiweng-audiollm-resource-1373259071:diagnostics/tsasr-farfield-target-absent-20261124/`，speaker-enroll 2026-11-24 交付。
  - 一场手机远场录音的公司会议，约 13.5 分钟，4 个已注册的人。
  - 目标人没说话的请求共 140 次，有 67 次输出了字（47.9%）。同一服务在 AISHELL-4 测试集上的同口径是 3.8%（11-16 反馈包）。
  - 包里共 100 条请求：误报 67 条（`absent_dup` 34 条、`absent_other` 33 条），`present_others_words` 3 条，对照 30 条。
  - 谁在说话按 MOSS 的说话人切分判定，没有人工标注。
- **模型**：amphion-119 `127.0.0.1:18207` 上的线上 11.17 TS 服务（`amphionasr-1.7b-v3-v18aes-mtp-candidate`）。
  - 请求格式与 speaker-enroll 相同：注册音频取前 5 秒，不足补零，后面直接接待识别片段；系统提示为 `TS_SYSTEM`，temperature 0。
  - 这个格式与训练一致：注册在前、片段在后，中间不加静音，[SEP] 由服务按 5 秒插入（`src/open_audio_llm/tsasr/ts_prompt.py`、`concat_audio.py`）。
- **声纹**：CAM++（zh-cn，`scripts/spk_embed.py`，任务 19 用过的同一个）。

## 要回答的问题

这场会议里，目标人没说话时将近一半请求仍有输出，原因在哪一层？候选原因：音量、注册音频混了别人的声音、请求格式、模型分不清声音相近的人、训练数据的分布。

## 方法

同一批 100 条请求，只改一处，其余不变，发给线上 11.17 服务：

1. **原样**：复现记录，检验结果稳定。
2. **音量**：整条请求峰值归一到 -3 dBFS，中位数提高 7.1 dB，模拟手机端的自动增益。
3. **换成会议外的陌生人**：目标人的注册换成与这场会议无关的人，各 4 份，按 case 编号轮换。
   - AISHELL-4 远场：取自 11-16 反馈包的注册；
   - AISHELL-3 录音棚：测试集说话人。
4. **换成声音同样相近的会议外注册**：
   - 候选池共 941 人：KeSpeech 手机录音 800 人，加 11-16 包的 AISHELL-4 远场注册 142 份。
   - 每条误报，用 CAM++ 比较候选注册和片段里实际说话那人的声音，选两种注册：
     - `match_max`：池里最像的；
     - `match_eq`：相似度不低于原注册、且最接近原注册的那份。
5. **注册音频有没有混入别人**：每份注册按来源时段（`enroll_ranges`）切成小段，共 45 段，与每个人的其他注册比 CAM++ 相似度。
6. **训练配方里这种情况占多少**：统计 v96 配方（任务 25 的回放配置 `configs/train-data-encreplay.yaml`）各 TS 来源的采样权重。

脚本：`scripts/farfield_spk_check.py`、`farfield_build_variants.py`、`farfield_voice_match.py`、`farfield_send.py`。原始输出在 `attempts/001/`。

## 结果

**输出了字的条数**（不在场 = `absent_dup` + `absent_other`，共 67 条；在场 = `present_others_words` + 对照，共 33 条）：

| 改动 | 不在场 | 在场 |
|---|---:|---:|
| 原样（与记录一字不差 92/100） | 66/67 | 33/33 |
| 音量 +7 dB | 65/67 | 33/33 |
| 注册换成 AISHELL-4 远场陌生人 | 0/67 | 0/33 |
| 注册换成 AISHELL-3 录音棚陌生人 | 0/67 | 0/33 |
| 注册换成会议外最像的人（`match_max`） | 31/67 | — |
| 注册换成会议外、相似度不低于原注册的人（`match_eq`） | 28/67 | — |

**按声音相似度分档看**（片段里实际说话的人和注册之间的 CAM++ 余弦）：

| 相似度 | 会议内的注册（原样） | 会议外的注册（`match_eq`） |
|---|---:|---:|
| < 0.30 | 12/12 | 2/12 |
| 0.30–0.40 | 15/15 | 13/31 |
| 0.40–0.50 | 19/19 | 7/18 |
| ≥ 0.50 | 20/21 | 6/6 |

- **同等相似度下对比**：29 条找到了不低于原注册相似度的会议外注册。原样 29 条全部输出；换成会议外注册后只有 9 条输出（31%）。
- **CAM++ 本身**：38/67 条里，会议内注册比 941 个外人都更像片段里说话的人（排名中位数 0）。会议内注册和说话人之间的相似度中位数 0.441，会议外最像的那位是 0.386。
  - 全部片段里，同一人的相似度均值 0.565，不同人 0.365，AUC 0.85。
  - 85a5c1 与 62c442 两人的注册彼此相似度 0.51，误报大多出在这两人之间。
- **注册纯净度**：45 段里没有一段更像别人。与其他人的最高相似度 0.56，都低于与本人其他注册的相似度。所以注册没混入别人。
- **训练配方**（v96，TS 采样权重占比）：

  | 情况 | 占 TS 采样 |
  |---|---:|
  | 注册来自同一录音，目标在说话 | 25.8% |
  | 注册来自同一录音，目标没说话（各会议数据的 `train_neg`） | 1.6% |
  | 注册与混音来自不同录音（模拟），目标在说话 | 57.7% |
  | 注册与混音来自不同录音（模拟），目标没说话 | 2.6% |
  | 热词 TS | 12.2% |

  - 注册来自同一录音时，训练里目标没说话的概率只有 5.8%。部署时 speaker-enroll 把每段话发给每个已注册的人，这场会议是 140/282 ≈ 50%。
  - 配方里给 aishellmix / librimix 配了相近声音的干扰表（`lookalike_table`），但没有一个来源设 `lookalike_prob`，所以训练时从没用过声音相近的干扰人。

## 结论

1. **以下几项都不是原因**：
   - 音量：提高 7 dB，误报不变；
   - 注册混入别人：45 段都更像本人；
   - 请求格式：与训练一致；
   - 服务的随机性：重放 92/100 一字不差。
2. **模型确实在用注册音频**：注册换成会议外的陌生人后，100 条全部不出字，包括原本该出字的 33 条。
3. **模型把"和注册在同一场录音里"当成"就是目标人"**：会议外的注册即使和说话人一样像、甚至更像，也只有 31% 被当成目标人；会议内的注册，相似度不到 0.3 时也 12/12 全部被认成目标人。
4. **这和训练分布一致**：注册与混音来自同一录音的训练样本里，94% 的目标人在说话；"同场的另一个人在说话、目标人没说话"只占 TS 训练的 1.6%，相近声音的干扰也没开。部署时这种请求约占一半。
   - 所以模型学到的是"同一场录音、声音差不多，就是目标人"。
   - 这个先验在 AISHELL-4 这种训练里见过的会议上影响小（3.8%）。在声音相近、手机远场的会议里，声音本身区分度低，先验就占了上风。这是推断：没有在 AISHELL-4 上做同样的控制实验。

**根因层：数据契约。** 训练分布里几乎没有部署时最常见的"同场他人"负样本。任务 25 的回放蒸馏把编码器拉向 11.17，这个先验也一并保留，所以任务 25 解决不了这个问题。

**局限**：
- 只有一场会议、4 个注册的人。
- 谁在说话靠 MOSS 判定。
- 包里的误报是按"原样有输出"挑出来的，原样一栏的 100% 是挑选造成的。会议外注册在同一批片段上的 31%，同样受这种挑选影响（偏向容易被接受的片段），只能作为下限对比。
- CAM++ 的相似度里也含信道成分。

## 修复方向（建议，待排期）

1. **训练数据**：做和部署同形的会议负样本。
   - 来源用真实会议训练集（AISHELL-4、AliMeeting、AMI 等），这些数据已有逐句时间线（`ts_window_utts`）。
   - 按单人话段切片，每段配会议里每个人的同场注册：说话人本人是正样本，其他人是负样本。负样本比例接近部署时的比例，并优先同性别、声音相近的人。
   - 加手机远场和低音量的增强。
   - 同时打开相近声音干扰（`lookalike_prob`）。
2. **守门**：加一项和部署同形的会议误报，用 AISHELL-4 / AliMeeting 测试集，按话段 × 全部与会人发请求，报不在场误报率和在场漏识。这次的反馈包作为回归探针。
3. **训练方式**：沿用任务 25 的冻结 LLM、只训编码器、回放蒸馏，避免继续 SFT 带来的漂移。新负样本作为监督数据加进去。要先确认问题出在编码器还是 LLM：可以用任务 23 的只换编码器方式，在这批请求上比较。
