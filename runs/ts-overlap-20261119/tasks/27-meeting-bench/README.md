# 27 会议误报定位基准（先定位，再训练）

## 输入

- **用户决定**（2026-11-25）：先做能定位问题的 Benchmark，再做训练调优。
- **要定位的问题**：下游反馈的手机远场会议（任务 26）里，目标人没说话时 11.17 仍有 47.9% 的请求输出了字；同一服务在 AISHELL-4 上是 3.8%。
- **已有基础**：`ts_asr_real@meeting-v3-20261117`（AISHELL-4 test 20 场会议，按下游 speaker-enroll 的方式把每段话发给每个注册人，24,342 条不在场请求），由 audio-data-contract `scripts/ts_real/meeting_segments.py` 等生成。
  - 11.17 在上面的不在场误报 3.78%，与下游 AISHELL-4 的 3.8% 一致，说明这种构造与部署对得上。
  - 11.17 的结果：`/workspace/data/ae-runs/amphionasr-v18aes-mtppkg/runs/run-20261118T032553Z-c4188122`。

## 要回答的问题

误报从 4% 涨到 48%，是哪个因素造成的？候选：
1. 声音相近：区分不了声音相近的人；
2. 同场先验：把"注册来自这场录音"当成目标人在说话的证据（任务 26 的假设；任务 26 的数据有选择偏差，不能证明）；
3. 远场声学：注册和片段共享房间远场声学，模型把声学匹配当成了人的匹配；
4. 低信噪比：手机远场的录音只比底噪高 6–10 dB；
5. 段长、重叠、会议人数。

## 方法

**基准**：`ts_asr_real@meeting-v4-20261125`（audio-data-contract `scripts/ts_real/meeting_controls.py`），加上 AISHELL-4 的 meeting-v3。

- **发送方式与 meeting-v3 完全相同**：
  - 分段：同一人相邻语句间隔 ≤ 1 秒、中间没有别人开口时并成一段，最长 10 秒。
  - 注册：每人一份，取本人在会上最早的干净语句，过声纹核对，客户端取前 5 秒。
  - 请求：每段发给会上每个注册人。本人在段前后 0.5 秒内都没说话算不在场，本人在段内说话 ≥ 0.5 秒算在场。
  - 去掉插在别人话里的短段，以及声纹核对判定标错人的段。
- **语料**：
  - AISHELL-4（5–7 人，远场阵列）；
  - AliMeeting test（20 场，2–4 人，远场阵列，另有每人的头戴麦）；
  - MagicData-RAMC test（两人手机对话；去掉含训练集说话人的录音）。
- **对照**：每组只改一处，与基础请求逐条配对（`metadata.base`）。

| 对照 | 改了什么 | 回答哪个问题 |
|---|---|---|
| 基础 | — | 误报随声纹相似度、段长、重叠、会议人数的变化（1、5） |
| `-xrec`（AliMeeting、RAMC，不在场） | 注册换成同语料另一场录音里的人，与段内最像的在场人的声纹相似度与原注册最接近 | 同等相似度下，同场注册是否更容易被接受（2） |
| `-enear`（AliMeeting） | 注册改取本人头戴麦的同一批语句，段不变 | 注册不再带房间声学后，误报是否下降、漏识是否上升（3） |
| `-near`（AliMeeting） | 注册和段都取头戴麦 | 近讲时声音是否就能分开（区分能力的上限） |
| `-snr`（AliMeeting） | 注册和段都加同一条真实会议室底噪，段的中位信噪比 8 dB，注册不低于 6 dB | 低信噪比本身能让误报涨多少（4） |

- **指标**（[meeting_fa_report.py](../../scripts/meeting_fa_report.py)）：
  - 每个划分报不在场误报率，以及在场的漏识率和字错率。只看误报会把"少输出"当成改进。
  - 基础组按声纹相似度、段长、重叠、会议人数分档。
  - 每组对照与基础请求逐条配对求差，95% 区间按录音整场重抽样的 bootstrap 计算（同一场会议的请求不独立）。
  - `-xrec` 另报相似度差 ≤ 0.05 的配对。
- **推理**：部署栈。pack-mtp 的 vLLM 服务，不开 MTP，与交付守门相同（[job_meeting_bench.sh](../../scripts/job_meeting_bench.sh)、[eval_lanes.sh](../../scripts/eval_lanes.sh)），每次评测接入 W&B。
- **文本核对**：
  - meeting-v3 的标注核对还有一项文本检查：普通识别转写里有连续 ≥ 3 个字、标注里没有，就判为标注漏字。
  - 这项检查需要每段的普通识别结果，所以和 11.17 的基线评测放在同一个 ACP 任务里跑。
  - 跑完后派生出去掉问题段的版本，记录 ID 不变，基线结果可以直接复用。

## 结论

1. **基准可用**。
   - AISHELL-4 部分复现了下游的 3.8%。
   - 各组对照配对完整，别场注册的相似度匹配覆盖 96–100%。
   - 下游那场会议的误报量级（约 45%）在 AliMeeting 上能复现：声音相近，再加上低信噪比。
2. **声音相近是前提**：相似度 < 0.3 时，各条件下的误报都在 3% 以内。总误报主要由相似度 ≥ 0.4 的少数请求决定，所以不同会议之间差一个数量级很正常。比较模型时要看这一档，不能只看总数。
3. **同场先验成立，机制是注册与段的声学匹配**（这次是在没经过挑选的数据上检验的，取代任务 26 的结论 3）：
   - 相似度相同时，同场注册的误报是别场注册的 3–6 倍（AliMeeting 0.4–0.5 档 44% 对 14%，RAMC ≥ 0.5 档 52% 对 8%）。
   - 只把注册换成同一个人的耳麦录音，相似度 ≥ 0.4 时误报就从 30–35% 降到 6–12%。两边都换回近讲、声学重新匹配后，又回升到 13–20%。
   - 代价：近讲注册让在场漏识 +3.5 个点。说明模型在接受真目标时同样依赖声学匹配，它学到的是"注册和这段听起来是不是同一个录音环境"，而不只是"是不是同一个人的声音"。
4. **低信噪比和短段放大误报**：信噪比降到 8 dB，误报 +3.4 个点，相似度 ≥ 0.4 时到 43–45%。段长 < 4 秒时，相似度 0.3–0.4 档的误报约翻倍。
5. **根因层：数据契约**。
   - 训练里同场注册几乎都是正样本：任务 26 统计的 v96 配方，同场负样本占 TS 的 1.6%。
   - 别场注册几乎都是模拟混音里不相关的人。
   - 所以模型能用"录音环境像不像"走捷径，而且这个捷径在训练分布里几乎总是对的。

## 训练调优的方向（下一步）

按上面的定位，修法要同时满足两条：一是同场、声音相近的人要被拒绝；二是换了设备的真目标要被接受。只做其中一条，会把误报换成漏识，或者反过来。

1. **同场负样本**：从真实会议训练集（AISHELL-4、AliMeeting train 等）按本基准的方式切段，每段配会上每个人的同场注册，提高相似度 ≥ 0.4 的人的比例。
2. **跨信道正样本**：同一人的注册取另一个信道或另一场录音，例如 AliMeeting train 的头戴麦注册配远场段，让"接受"不能只靠声学匹配。
3. **一致的低信噪比增强**：注册和段加同一条底噪。
4. **守门**：
   - 本基准：不在场误报，以及相似度 ≥ 0.4 档的误报；
   - 近讲注册组的漏识；
   - 现有的 v12、英文 TS 误报、中文普通识别。

## 局限

- AliMeeting 有 3 场会议（9 人）没有可作注册的语句，抢话最密的会议没进基准。
- 低信噪比组只加了稳态的会议室底噪，没有模拟手机的自动增益和编解码。
- 声纹相似度用的是 ECAPA，它本身也受信道影响。所以"相似度相同"只是在 ECAPA 看来相同。近讲注册这组正是为了绕开这一点。
- RAMC 只有 37 段录音，区间宽。
