2026-11-21 用户同意转向"从 11.17 起做 GRPO，用重叠样本上的转写准确率做奖励"。

## 设计

与第 26 轮只差三处，配置由 [make_grpo_configs.py](../../scripts/make_grpo_configs.py) 生成：

1. **计划**：在 v26 的五份之外，加 `ts-transcribe`（[grpo_mining_plans.py](../../scripts/grpo_mining_plans.py)），份额 0.12。
   - 入选条件：TS、目标在场、16 次全都写了字、没有热词分歧，且"达到组内最好准确率"的样本和没达到的样本各至少 2 条。
   - 另外五份计划的份额不变（0.15 / 0.08 / 0.10 / 0.06 / 0.06），回放从 0.55 降到 0.43。
   - 在 v26 的挖掘结果上核对过：前五份计划逐条数与 v26 完全相同，`ts-transcribe` 4,080 条。
2. **训练文本**：数据配置里有终版的 104 个训练来源换成终版（`final_versions.py`，用户 2026-11-21 要求所有任务切终版）。挖掘来源同样换成终版（plain 5 / miss 12 / ts 38 个）。
3. **代码**：`shared/code-v4` = main 15eacbf。
   - 第 26 轮用的是 code-v16；15eacbf 是上下文纠偏 GRPO（`runs/zh-ctx-grpo-20261120`）在终版文本上跑通的版本（含 #171、#172）。
   - 挖题服务配置从那边复制（vLLM 0.32、TS SEP 与逐请求注册长度的修复），模型换成 11.17。

训练参数与第 26 轮相同（第十轮配方：lr 1e-6、beta 0.04、400 步、每步 32 条音频 × 8 个采样、温度 1、联合 MTP 权重 0.1）；奖励同第 26 轮：准确率、出字判断、热词、格式。

训练后照第 26 轮做两个候选：第 200/300/400 步平均（avg3），以及 avg3 与 11.17 各一半的插值（interp050）。

中文普通识别（门槛 4.39）：12 avg3 4.41、interp050 4.36（11.17 4.39）；英文普通识别 8.03 / 8.05（11.17 8.06）。GRPO 没有像任务 03/04/07/08/11 的 SFT 那样损伤普通识别。

- **重叠转写**：重叠 ≥ 0.9 只比 11.17 低约 0.1 个点，与 v26 的差别也在 0.1 以内，没有实质改变。
  - 原因在计划的入选规则。规则只要求组内有人达到最好准确率、有人没达到，于是 4,138 条里 53% 平均准确率 ≥ 0.95，48% 组内最好与最差只差不到 0.1（一两个字）。只有 21.6% 相差 ≥ 0.3，7.4% 的最好一次比中位数高 ≥ 0.2。
  - GRPO 按组内标准差归一化优势，这些近乎打平的组和真正写错的组推得一样重。
- **出字门槛**：误报 + 漏识的总数和 11.17 几乎一样（interp050 692，11.17 699），变的只是分配。
  - 新增漏识集中在没有干扰人（74 → 128）、重叠为 0（64 → 104）、近远讲（10 → 28）、短注册（60 → 87）、交接（2 → 9）的样本上。
  - 减少的误报集中在干扰人与目标同样响或更响的样本上。
  - 也就是"是不是目标人"的判断调严了，和复盘里"各轮只在误报和漏识之间换"的现象一致。这和 v26 同方向，本任务更明显，可能因为回放份额从 0.55 降到了 0.43（未核实）。
