# 25 冻结 LLM、只训编码器，回放 11.17 原有任务（蒸馏）

## 要回答的问题

任务 23 的只换编码器诊断说明了两点：
- 重叠收益在编码器里。全量 v12 上，重叠 ≥ 0.9 的错误率 18.27% → 15.85%（−2.42 [−3.11, −1.68]）。
- 灾难性遗忘在 LLM 里，编码器本身也有中等漂移：v12 误报 342 → 545，中文普通识别 4.39 → 6.31，英文 TS 误报 655 → 1558。

这一轮要回答：冻结 LLM、只训编码器，并在 11.17 原有任务上把编码器拉住，能否保住重叠收益，同时让误报和普通识别回到守门以内。

## 方法

- **起点和可训练部分**：起点 11.17。只训音频塔，包括卷积前端和投影层；LLM 冻结，包括 MTP 头。学习率 2e-5，余弦衰减，共 3 万步，与任务 23 相同。
- **模拟重叠场景**：沿用任务 23 的目标，即目标文本交叉熵，加第 6、12 层 mel 掩码辅助（权重 4）。
  - 说话人池用终版 v2 文本：`tse_data.setup("train_final2")`，包括 AISHELL-3 录音棚、KeSpeech + MagicData + AISHELL-2 手机、AISHELL 朗读。
  - 每步 16 卡 × 4 条场景，15% 换别人的注册，标准答案为不在场。
- **回放 11.17 原有任务**：用 v96 配方的全部任务（[../../configs/train-data-encreplay.yaml](../../configs/train-data-encreplay.yaml)），包括中英西葡普通识别、热词、中英 TS 在线混音、真实 TS 录音和各类负样本。
  - 该配置由任务 08 的数据配置经 `to_final_v1.py` 切到终版 v2：切换 124 个训练源，`ts_nonspeech_pool@es-babble-20261110` 无需终版，保持不变。
  - 回放上只算 KL(11.17 ‖ 学生)，覆盖全部监督 token，不算交叉熵。老师就是 11.17：冻结的原始音频塔加同一个冻结的 LLM。所以开训时 KL 为 0，它只起"拉住漂移"的作用。
  - 不用交叉熵的原因：任务 08 冻结 LLM、在这套配方上用标注做交叉熵，每个重叠档都比 11.17 差，误报也升高。
- **总损失**：CE_模拟 + 4 × 掩码辅助 + 1 × KL_回放。每步一个模拟 micro-batch 加一个回放 batch；回放 batch 按配方的时长分批，最多 320 秒或 8 条。
- **脚本**：
  - 训练 [ft_enc_replay.py](../../scripts/ft_enc_replay.py)；
  - ACP 2 节点任务 [job_encreplay.sh](../../scripts/job_encreplay.sh)；
  - 训完用任务 23 的方式评第 1、2、3 万步：模拟重叠集、副作用集、掩码探针；
  - 再用部署栈跑守门（[job_e2e2_gate.sh](../../scripts/job_e2e2_gate.sh)）。

## 结论（attempt 001，只限模拟集）

1. 冻结 LLM、只训编码器并加回放蒸馏，模拟重叠上的收益比任务 23（全参数）更大：第 3 万步 14.15% → 10.61%（任务 23 是 12.14%），2 个干扰人 −4.06，显著。
2. 干净输入也变好（−1.40，区间刚好不含 0），说明编码器的识别本身没有被拉坏。
3. 第 2 万步与第 3 万步几乎相同，已基本收敛。
4. **未验证**：这里只有中文模拟数据和 HF 解码。完成条件里的交付守门（v12、英文 TS 误报、中文普通识别、全量 v12 重叠配对）要用部署栈在 ACP 上跑。2026-11-25 ACP 的 2 个节点被 ts-robust 的任务占着，等有节点再跑。
5. 真实会议里目标不在场的误输出（任务 26）不是本任务的目标：回放蒸馏把编码器拉向 11.17，11.17 在这类请求上的行为也一并保留。候选还要在任务 27 的会议基准上看。
