# 18 重叠信息能不能恢复，丢在编码器还是解码器

## 要回答的问题

用户 2026-11-22 要求给出本质结论：v12 重叠 ≥ 0.9 的转写错误，是音频本身已经不可恢复，还是可恢复但编码器或解码器能力不够。

分三步回答：

1. **物理上可不可恢复**：用理想时频掩码（拿真实单独音轨算）分离混音，再交给 11.17。
2. **编码器输出里有没有目标的内容**：在冻结的 11.17 编码器各层上训探针，比较能取出多少。
3. **哪个部件学得会**：在和 v12 同一生成器的数据上，分别只训编码器、只训 LLM、两者都训，看谁能补上差距。

## 输入

  - 用该版本的生成代码重放场景（audio-data-contract 3f9c7ca 的 `scripts/ts_benchmark/{build,mixer}.py`，配方与种子不变，噪声与混响用存档里的文件），渲染目标人、干扰人、噪声三条音轨。

  - 脚本：[ovr_stems.py](../../scripts/ovr_stems.py)、[ovr_stems_lib.py](../../scripts/ovr_stems_lib.py)。

## 结果

### 第 1 步：重叠音频是可恢复的

| 615 条，11.17 转写错误 | 全部 | 1 个干扰人 | 2 个干扰人 |
|---|---:|---:|---:|
| 原混音 | 14.50% | 11.17% | 16.92% |
| 去掉干扰人（噪声保留） | 6.69% | 5.88% | 7.28% |
| 理想二值掩码（保留目标占优的时频点，32 ms 窗） | 8.09% | 6.24% | 9.44% |
| 理想比例掩码 | 5.76% | 4.91% | 6.37% |

- 干扰带来的损失 7.81 个点。理想二值掩码收回 6.41 个点（82%，区间 [4.29, 8.42]），只剩 1.40 个点 [0.22, 2.69]。理想比例掩码收回全部，还压掉了一部分噪声。
- **被干扰人和噪声压住的目标能量平均只有 6.1%**；目标能量集中的时频点里，77% 目标比其余高 3 dB 以上。
- 按被压住的比例分三档（< 3.8%、3.8–6.8%、> 6.8%），原混音错误 12.17 / 13.56 / 17.11%，理想比例掩码 5.47 / 5.80 / 5.94%。最难的一档也能恢复。
- 11.17 原混音错 ≥ 30% 的 92 条：原混音 69.6%，理想比例掩码 19.9%，去掉干扰人 23.3%。它们去掉干扰也要错 23%，这部分来自噪声、混响和注册质量，和重叠无关。

**结论：**重叠时多出的错误，基本都是"目标的信息在混音里，模型没有分出来"，不是物理上被盖住。

### 第 2 步：从冻结的编码器输出里，额外训的小网络取不出更多

**CTC 探针**：4 层 Transformer（d 512）加 CTC，直接从某一层特征输出目标的字。训练数据是 18,400 条训练场景，原混音和去掉干扰人各一份。

| 615 条 | 原混音 | 去掉干扰人 | 干扰损失 |
|---|---:|---:|---:|
| 11.17（LLM 解码） | 14.50% | 6.69% | 7.8 |
| 编码器输出（送入 LLM 的 2048 维） | 31.11% | 19.79% | 11.3 |
| 第 24 层 | 31.36% | 18.45% | 12.9 |
| 第 12 层 | 68.08% | 52.46% | 15.6 |
| 第 0 层（卷积之后） | 99.0% | 99.1% | — |

探针在留出的训练分布样本上去掉干扰人时只错约 3%，到 v12 上错 18–20%：它记住了训练句子，换成没见过的句子就不行。所以这个探针只能说明"它不比 LLM 取得多"，不能确定信息有没有。

**去干扰映射器**：在第 ℓ 层插一个残差 Transformer（4 层，d 768，初始化为恒等）。它从原混音的第 ℓ 层特征，预测去掉干扰人后同一帧的第 ℓ 层特征，监督是逐帧特征而不是文字。映射后的特征送回 11.17，由后续编码层和 LLM 照常解码（HF，和 vLLM 逐条核对一致）。

| 615 条 | 留出集特征偏差（恒等 → 映射） | 转写错误 | 与无映射之差 [95%] |
|---|---:|---:|---:|
| 11.17（HF，无映射） | — | 14.15% | — |
| 第 12 层 | 0.82 → 0.30 | 19.23% | +5.08 [+3.23, +6.89] |
| 第 24 层 | 0.67 → 0.25 | 15.31% | +1.16 [−0.43, +2.69] |
| 编码器输出 | 0.61 → 0.18 | 14.95% | +0.80 [−0.86, +2.37] |

- 映射器把特征偏差去掉了六到七成，但转写没有变好。它去掉的是和内容无关的部分，区分目标说了什么的那部分预测不出来。
- 两种探针一致：**在 11.17 编码器的各层输出上，额外训的网络都没能比 11.17 自己取出更多目标内容。**这支持"信息在编码器里已经纠缠或丢失"，但仍可能是探针不够强，所以做第 3 步。

### 第 3 步：分部件微调，只有干净输入变好，重叠差距补不上

从 11.17 起，在 101,200 条训练场景上训 3000 步，每步 16 条，共 4.8 万条，不到半轮。
- 每条以 0.7 的概率用原混音、0.3 的概率用去掉干扰人的版本，损失是目标文本的交叉熵。
- 标注是参考文本，标点按 11.17 在干净版本上的输出搬过来。这样标点风格一致，起步损失约 0.12；不带标点时是 1.5–2.5。
- 学习率：编码器 2e-5，LLM 1e-5。
- 三组：只训音频编码器（3.18 亿参数，LLM 冻结）、只训 LLM（17.2 亿参数）、两者都训。

| 615 条，HF 解码 | 原混音 | 与 11.17 之差 [95%] | 去掉干扰人 | 与 11.17 之差 [95%] | 干扰损失 |
|---|---:|---:|---:|---:|---:|
| 11.17 | 14.15% | — | 6.45% | — | 7.70 |
| 只训编码器 | 16.84% | +2.69 [+0.84, +4.48] | 5.20% | −1.25 [−2.59, −0.10] | 11.64 |
| 只训 LLM | 13.04% | −1.11 [−2.71, +0.45] | 4.09% | −2.36 [−3.61, −1.22] | 8.95 |
| 两者都训 | 18.26% | +4.11 [+2.15, +5.96] | 5.92% | −0.53 [−1.90, +0.74] | 12.34 |

2 个干扰人时：只训编码器 16.46 → 21.04%，两者都训 22.13%，只训 LLM 15.80%。

- **只训 LLM**：干净输入显著变好（−2.4），原混音只降 1.1 且不显著，干扰损失没有缩小（7.70 → 8.95）。训练确实有效，学到的是对这批数据条件的适应，不是重叠下的分离。
- **训编码器**（单独或连同 LLM）：干净输入变好，原混音反而显著变差，2 个干扰人时最严重。测试说话人没在训练里出现过，编码器学到的是认训练说话人的捷径，不能推广。这和任务 03/04/07/08 一致：只要动编码器，选择性下降，抄干扰人变多。

## 结论

1. **重叠音频本身是可恢复的。**理想比例掩码下 11.17 只错 5.76%，比去掉干扰人还低；被盖住的目标能量平均只有 6%。重叠带来的 7.8 个点损失，物理上全部可以收回。
2. **瓶颈不在解码器。**两种证据：
   - 在编码器输出上额外训的探针和映射器，取不出比 11.17 更多的目标内容；
   - 只训 LLM 时，干净输入明显变好，重叠损失却不缩小。
3. **瓶颈在编码器：它没有把目标从两三个人的混音里分出来，而且用文本交叉熵学不出能推广的分离能力。**
   - 编码器拿到理想分离后的输入时，整个模型只错 5.8%；
   - 它对原混音的输出里，目标内容已经丢失或缠在一起，后面接什么都取不出来；
   - 在匹配分布的 4.8 万条数据上训它，干净输入变好，重叠反而变差，学到的是训练说话人的捷径。
   
   以前所有 SFT、辅助损失、循环编码器的尝试（任务 03/04/07/08/11），都是从这一层的文本或特征监督出发，所以都没有动到重叠转写。
4. **对下一步的含义**：需要一个直接针对分离、并且说话人足够多样的训练信号，作用在编码器之前或编码器底层。
   - 例如：以注册为条件预测理想比例掩码。现在能为任意数量的生成场景给出精确的单独音轨，所以能拿到这个目标。
   - 理想比例掩码 5.76% 就是这条路的上限。任务 17 里公开盲分离模型失败，是数据不匹配，不是这条路走不通。

局限：
- 测试的是 v12 的合成场景（主数据集，重叠 ≥ 0.9，1–2 个干扰人）。
- 理想掩码用了真实单独音轨，是上限，不是能实际做到的值。
- 第 3 步只用了一组学习率和 3000 步。编码器那组的退化方向明确，和以往一致，但更小的学习率或更多说话人可能缓解。
