# 29 仿真流补负样本、加普通识别回放：过交付守门

## 要回答的问题

任务 28 attempt 002 的重叠收益已经够了（v12 重叠 ≥ 0.9 比 11.17 降 4.55 个点），但有三道交付守门没过：v12 误报、英文 TS 误报、中文普通识别。它们和任务 25 一样，是共有的训练方式造成的。任务 28 已经定位了原因（[任务 28 · 守门未过项的定位](../28-meeting-negatives/README.md#attempt-002-之后守门未过项的定位2026-11-27)）：

- **v12 误报**：仿真流的交叉熵里缺两类负样本，一是没人说话，二是短句里声音相近的人。这两类只靠 KL 回放约束。
- **中文普通识别**有两个来源：
  - TALCS 中英混说（+0.155）：回放里根本没有 TALCS；
  - WenetSpeech 短句（约 +0.10）：KL 是软约束，留下了残差。回放按 11.17 的配方混合，普通识别只占 22%，WenetSpeech 只占 3.6%。

这一轮要回答两个问题：
1. 把缺的负样本补进交叉熵，v12 误报能不能回到门槛内？
2. 加一路普通识别的 KL 回放（含 TALCS），中文普通识别能不能回到门槛内？代价是不是重叠收益？

## 方法

两组，各用 2 个节点跑 3 万步。除下表列出的差别外，两组都与任务 28 attempt 002 相同：
- 起点 11.17，冻结 LLM，只训音频塔；
- 仿真流：交叉熵加掩码辅助；
- 回放：对 11.17 做 KL；
- 会议流：用 attempt 002 隔离过的规划。

| 组 | 仿真流补负样本 | 普通识别回放 |
|---|---|---|
| `simneg` | 加 | 不加 |
| `simneg-asr` | 加 | 加 |

`simneg-asr` 是候选组。`simneg` 是对照组，两组之差就是普通识别回放的效果，包括它对重叠收益的代价。用户 2026-11-27 的意见是"在有空闲节点的情况下……用实验来推进"，所以两组同时跑，不另等决定。

**仿真流补负样本**（[ft_enc_replay.py](../../scripts/ft_enc_replay.py) 的 `SIM_NEG=0.15`）：
- **怎么抽**：每个仿真样本有 15% 的概率改用 v12 生成器里目标不在场的场景，三类各占三分之一，答案都是 `language None`。

  | 类别 | 场景 |
  |---|---|
  | 无人说话 | `nonspeech-*`，共 6 个 |
  | 短句 | `abs-short`；nearshort 配方的 `short-rand-neg`、`short-hard-neg` |
  | 其他不在场 | 共 46 个：`abs-*`，以及注册劣化、信道、面板、压力各组的 `-neg`（含混音效果） |

- **场景来源**：生成器配方 v4-20261022；nearshort 配方取自 adc `scripts/ts_benchmark/recipe-nearshort.yaml` v3-20261022。
- **配对的在场样本**：nearshort 的 `solo-short-pos`、`short-k1-pos` 加入在场场景（共 57 个），场景形状和短句负样本相同，用来抵消"短就判不在场"的倾向。
- **原有负样本不变**：随机换注册的负样本，仍占在场样本的 15%。
- **实际比例**：在场约 72%，换注册约 13%，生成器负样本 15%。每 20 步记一次实际发出的比例和相近声音负样本的平均相似度，用来核对配置真的生效。
- **说话人**：只用训练集说话人（`train_final2`，26,585 人）。用到测试人员真实注册录音的场景（`realreg*`，v12 用的那几段）不用。
- **相近声音负样本**（`hard`）：
  - 注册人取与干扰人声音最近的 5 人之一，声纹用基准同一个模型（WeSpeaker ECAPA-TDNN512-LM，[train_speaker_embeddings.py](../../scripts/train_speaker_embeddings.py)）。
  - 在 2.6 万人里取最近的 5 人，比 v12 的测试池难得多：所选的人相似度中位数 0.66，v12 `short-hard-neg` 是 0.56。所以每个场景先随机取 600 人作候选池（`HARD_POOL`），模拟出的相似度为中位数 0.56、p10 0.48、p90 0.64，与 v12 一致。
- **噪声文件**：无人说话场景用 MUSAN noise/music 和 AudioSet 交通声，和 11.17 配方的 `nonspeech_sources` 是同一批文件，v12 的无人说话场景也裁自这些文件。这不是新增的评测集接触，但 v12 无人说话场景上的改善，分不清是泛化还是记住了文件。

**普通识别回放**（`ASR_REPLAY_CONFIG`，只在 `simneg-asr`）：
- **做法**：每步多一个回放 batch，取自 [train-data-asrreplay-t29.yaml](../../configs/train-data-asrreplay-t29.yaml)，KL 和权重与原回放相同。
- **数据**：原回放里全部普通识别来源（权重不变），再加 TALCS train。
- **TALCS 的版本**：TALCS 没有终版文本。带标点的版本 `punc-written-v1-20261029` 只登记了监督、没有录音映射，加载不了，所以改用 clean 版本 `clean-dual-qwen-moss-v1-20261009`，设 `require_clean_pass`（35 万条里通过 347,533 条）。这个版本的文本基本不带标点；KL 只拿它当老师强制的上下文。
- **TALCS 的权重**：与 AISHELL-2、KeSpeech 相同（1.9091）。
- **效果**：WenetSpeech 的回放量约为原来的 5.5 倍，TS 部分的回放不变。

**训练文本**：两组的主回放是 [train-data-encreplay-t29.yaml](../../configs/train-data-encreplay-t29.yaml)，即 attempt 002 的配方，只把 fleurs_zh 换成终版 v3。这两个配置由 [make_t29_configs.py](../../scripts/make_t29_configs.py) 生成。终版 v4（中文数字统一成阿拉伯数字）先不切：要等评测器把参考和输出都转换后再用，这是 amphiondata-58 11-27 的要求。

**评测**：与任务 28 相同。
- 第 1、2、3 万步跑模拟集，HF 解码；
- 导出第 3 万步（只换编码器），在部署栈上跑交付守门和会议基准（[job_gate_bench.sh](../../scripts/job_gate_bench.sh)）。
- **打分口径**：本轮和 11.17 的评测记录必须是同一打分版本（`summary.json` 的 `protocol.version`）才能比字错率。
  - 现在评测环境、11.17 和 attempt 002 的记录都是版本 3。
  - amphion-eval 11-27 合并了版本 5：中文参考和输出都先统一成阿拉伯数字再算字错率，误报、漏识不变。如果出守门时环境已经升到 5，先用 `ae open-audio-llm rescore` 给 11.17 重打分，再按同一规则（11.17 × 1.02）算中文的两道字错率门槛。
