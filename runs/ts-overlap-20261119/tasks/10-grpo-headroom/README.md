# 10 GRPO 在重叠转写上有没有可学的信号（只采样，不训练）

## 要回答的问题

2026-11-21 用户同意转向"从 11.17 起做 GRPO，用重叠样本上的转写准确率做奖励"。GRPO 只能强化模型自己采得到的更好答案：

- 一组采样的奖励全都一样，这条样本就没有信号；
- 贪心写错、16 次采样也没有一次更好的样本，GRPO 推不动。上下文纠偏那边 58% 的错题就属于这种（`runs/zh-ctx-grpo-20261120`）。

现有 GRPO 计划（`mining_plans.py`）只按"写不写"和热词奖励挑样本，没有按转写好坏挑的计划，所以以前的轮次从没用重叠转写做过信号。

## 输入

- 脚本：[../../scripts/probe_ts_sampling.py](../../scripts/probe_ts_sampling.py)。请求构造与评测相同（AmphionEval 的 `prepare_audio`、5 秒注册、`encode_for_server`、`parse_asr_output`）。打分用复盘 `decompose_errors.py` 的转写错误口径：AmphionEval 中文切分，(替换 + 漏字 + 多字) / 参考长度，空输出按全漏计。
- 模型：11.17（`model-afea989da22b77adc0ce9365`），用 11.17 守门的服务栈 pack-mtp（vLLM 0.18）。
- 样本：11.17 的 v12 评测 run `run-20261117T032925Z-961b82b3` 里目标在场、目标重叠率 ≥ 0.9 的中文 TS 样本。贪心结果直接用该 run 的输出。
- 每条在温度 1 下采 16 次。

## 完成条件

报出以下几项：
- 贪心写错的样本里，16 次中至少一次比贪心好的比例；
- 16 次里最好一次的平均转写错误（best-of-16），对比贪心；
- 组内奖励不全相同的样本比例。

## 结果

**GRPO 在重叠转写上有可学的信号**：贪心写错的样本里，三分之二能在 16 次采样中采到更好的答案。上下文纠偏那边 58% 的错题 16 次一次都没采对；两边口径不同（那边看是否全对，这里看是否比贪心好），这里按"全对"算也有 24.1%。

v12 目标在场、重叠 ≥ 0.9 的中文样本共 4,554 条。转写错误按字加权，空输出按全漏计：

| | 转写错误 |
|---|---:|
| 贪心（11.17 评测输出） | 18.27% |
| 温度 1 单次采样的平均 | 21.56% |
| 16 次里最好的一次 | 12.74% |

贪心写错的 2,144 条（47%）：

| | |
|---|---:|
| 16 次中至少一次比贪心好 | 66.5% |
| 16 次中有一次完全写对 | 24.1% |
| 16 次都不比贪心好 | 33.5% |
| 错字落在"有更好采样"的样本上的比例 | 73.6% |
| 每条平均有几次比贪心好 | 2.77 / 16 |

全部样本中，68.3% 的组内奖励不全相同，有信号；31.7% 全相同，大多是贪心本来就对的。单次采样输出为空的占 4.6%。

注意：
- 这是在测试集 v12 上量的。GRPO 训练用的是训练分布的提示，信号多少要在挖掘时再量。
- "比贪心好"包含温度 1 下碰巧少写错几个字的情况；这本来就是 GRPO 用来学习的信号。

## 对下一步的含义

- 奖励函数不用新写：已有 `qwen3_asr_accuracy`（1 − 字错率，`rewards/qwen3_asr.py`）。
- 缺的是挑提示的计划。现有挖掘规则（`mining_plans.py`）只留"写不写"有分歧（ts-present / miss / ts-absent / nonspeech）或热词奖励有分歧的提示。"写不写"一致、只在转写好坏上有分歧的 TS 提示全被丢掉了，以前的 GRPO 轮次因此从没在重叠转写上学过。
- 下一步：在 GRPO 挖掘里加一个"重叠转写"计划，挑出写不写一致、16 次的准确率奖励有分歧的 TS 提示（优先重叠 ≥ 0.6），从 11.17 起做 GRPO。
