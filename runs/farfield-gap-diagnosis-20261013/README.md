# 远场文字差距诊断（不训练）

## 问题

AliMeeting dev 120 秒窗口上，当前模型（zh-dialogue-18000）cpER 20.76，MOSS 15.64。拆解（同一窗口、按时间拼接的说话人无关字错误）显示约 4 个点来自文字，主要是替换（10.5 对 6.8），语气词只占约 0.7；138 个窗口中 MOSS 胜 124 个。要回答：这是基座远场能力不足，还是我们的微调损伤了识别，或是请求格式所致。

## 方法

AliMeeting Eval（8 场）人工标注语句中，前后 0.2 秒内没有其他说话人的单人语句，1–30 秒、至少 2 字，共 1,099 句、23 人、每种条件 0.94 小时。同一时间轴切两份：

- 远场：阵列 8 通道均值（与选模面板一致）。
- 近讲：该说话人自己的耳麦。

两份互相对齐（R8008_M8013 包络互相关最佳时延 0.04 秒）。参考文本相同，单说话人 SOT 目标，用 B 层同一 AmphionEval 分支的说话人无关 CER 打分。

| 模型配置 | 请求 |
| --- | --- |
| qwen3-asr-1.7b | 官方转写请求，官方推理配置 |
| zh-dialogue-18000 | 训练所用的说话人转写请求 |
| zh-dialogue-18000-plain | 同一模型，官方转写请求 |
| zh-emilia2-6000 | 说话人转写请求 |
| moss-transcribe-diarize | 官方 vLLM、transcriptions 接口 |

## 判读

- 基座远场 ≈ MOSS、我们更差：微调损伤，改训练方式。
- 基座与我们远场都明显差于 MOSS、近讲接近：远场声学能力不足，需要真实远场数据。
- 近讲也差：识别能力整体差距，与远场无关。
- 与 120 秒窗口结果对照，可估计重叠语音和长音频的额外损失。

## 结果（2026-10-13）

### 单人无重叠语句（字错误率 %，统一打分重算）

| 模型 | 远场 | 近讲 |
| --- | --- | --- |
| qwen3-asr-1.7b | **5.0** | **3.6** |
| moss-transcribe-diarize | 6.9 | 4.2 |
| zh-dialogue-18000-plain | 6.4 | 4.4 |
| zh-dialogue-18000 | 7.4 | 5.0 |
| zh-emilia2-6000 | 7.4 | 4.8 |

AmphionEval 对 18000-plain 远场报 10.7：1 条输出失控、反复输出"language"（673 个错误），未被复读规则识别；其余与重算一致。

### 窗口长度（AliMeeting Eval 同一批人工标注窗口，8 通道均值）

| 模型 | 30 秒 cpER / 说话人无关 | 120 秒 cpER / 说话人无关 |
| --- | --- | --- |
| zh-dialogue-18000 | 20.86 / 21.61 | 21.26 / 21.60 |
| moss-transcribe-diarize | 15.84 / 18.55 | 15.54 / 18.51 |

### 120 秒窗口错误按参考语句归类（选模面板 alimeeting_dev，按时间拼接对齐）

| 语句类别 | 文字占比 | 我们 | MOSS | 差距贡献 |
| --- | --- | --- | --- | --- |
| 与他人重叠、>3 字 | 72.7% | 24.8 | 20.2 | 3.35 点 |
| 与他人重叠、≤3 字 | 3.5% | 60.8 | 63.9 | −0.10 点 |
| 无重叠（含 0.5 秒内紧邻他人） | 23.8% | 8.5 | 6.2 | 0.57 点 |

训练数据多人窗口平均重叠率（各抽 3,000 个 120 秒窗口）：AliMeeting 34.1%、AliMeeting 近讲转远场模拟 28.7%、AISHELL-5 13.1%、AISHELL-4 9.9%、6–12 人合成约 11%、Emilia2 1.4%、RAMC 远场模拟 0.1%。

### 结论

1. 远场声学不是瓶颈：基座在远场单人语句上优于 MOSS。
2. 微调有损伤（单人远场 5.0 → 7.4，其中说话人转写格式约占 1 点），但在窗口差距中只占约 0.6 点。
3. 窗口长度不是原因（30 秒与 120 秒相同）。
4. 差距集中在与他人重叠的语句上（AliMeeting 76% 的参考文字属于这类语句），我们比 MOSS 高 4.6 点，贡献约 3.4 点。
5. 能教重叠识别的训练数据只有 AliMeeting（约 100 小时原始音频）及其模拟版本；Emilia2 几乎无重叠，所以它改善整场说话人一致性，却不改善窗口文字。
