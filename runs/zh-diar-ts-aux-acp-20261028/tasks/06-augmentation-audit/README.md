# 数据增强审计：配置里写的增强，训练时实际生效了多少

用户 2026-10-30：“数据增强在本训练框架中是否被正确启动，这也需要你彻查”。

## 结论

**每轮 80.6% 的训练样本没有任何波形增强**，包括被背熟的真实会议（35%）和 Emilia2 对话（20%）。它们唯一的增强是频谱遮挡，但强度几乎可以忽略。

配置写的是“变速 25%、加噪 50%、频谱遮挡 10%”，实际情况如下：

| 增强 | 配置 | 实际 | 原因 |
| --- | --- | --- | --- |
| 变速（0.95 / 1.0 / 1.05） | 25% | 所有带时间戳的多人转写数据都是 0。只有单人 ASR 和远场 ASR 回放（共约 12.6%）生效 | 代码看到带时间戳的格式就把变速关掉，因为变速后时间戳对不上；没有警告，也不会去换算时间戳（`catalog_dataset.py` 中 `sot_output_format in {TIMESTAMP_FORMAT, TARGET_FORMAT}` 的分支） |
| 加噪（MUSAN，SNR 0–15 dB） | 50% | 真实会议、Emilia2、AISHELL-5、远场模拟和多人词级合成都是 0。只有短句合成、中英混说、单人 ASR 生效（共约 14.8%） | 配方里写明 `noise_exclude_datasets`（“真实录音不加训练噪声”）。这是一项设计选择，当时没有做过对比 |
| 混响 | 未配置 | 0 | — |
| 频谱遮挡 | 10% | 确实作用到了模型输入特征，但每个样本只遮 1 段时间（≤20 帧 = 0.2 秒）和 1 段频带（≤8/128）。不管窗口是 30 秒还是 600 秒都一样，120 秒窗口被改动的特征只占约 1–2% | 遮挡次数不随窗口长度变化；原设定是按短句 ASR 定的 |

按实际生效的增强，统计每轮样本占比（E 组配方）：

| 实际生效 | 样本占比 |
| --- | --- |
| 什么都没有（只剩频谱遮挡） | **80.6%** |
| 只有变速 | 4.6% |
| 只有加噪 | 6.8% |
| 变速 + 加噪 | 8.0% |

另外，真实会议的“声道视角”版本每个窗口固定用一个麦克风，而不是每次随机选。所以每个真实会议窗口只有两种固定的声音版本，每一遍听到的音频完全相同。

## 证据

- `audit-e.json` / `audit-e.log`（`scripts/audit_augmentation.py`）：用 E 组的生效数据配置（`tasks/02-train-e/attempts/001/data-effective.yaml`）和训练代码快照 `shared/code` 构建训练数据集。每个数据版本取样本数最少的一个划分，抽 20 条，记录逐条生效的增强配置，以及波形是否被改动（长度变化 = 变速，数值变化 = 加噪或混响）、频谱遮挡策略是否传到模板。
- `spec-augment.log`（`scripts/audit_spec_augment.py`）：用真实训练模板，对同样 3 条 AliMeeting 训练窗口编码两遍（遮挡概率分别设为 1 和 0）。被遮挡的特征确实变成 0，被改动的数值占 0.9–2.3%。
- 遮挡概率的实测值 0.0–0.25 符合配置的 10%（每个来源只抽了 20 条）。

## 需要改的地方

- 变速：对带时间戳的转写，按变速倍数换算时间戳，而不是直接关掉。这样变速对 90% 以上的数据生效。
- 频谱遮挡：遮挡次数随窗口长度增加。
- 数据预检：报告每个来源实际生效的增强，避免“配置写了、实际没生效”再次被漏掉。
- 真实录音是否加噪，是一个超参数，要用评测来决定，不在这里直接改。
