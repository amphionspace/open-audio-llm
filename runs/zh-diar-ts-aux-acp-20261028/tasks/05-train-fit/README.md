# 训练集拟合诊断：模型是否已经背熟真实会议训练窗口

用户 2026-10-30 同意先做这项诊断（第一轮结论里的方案 1）。

## 问题

第一轮六组都在原地打转：真实会议 dev / test 没有变化，训练 loss 却在每轮学习率退火阶段从约 0.215 降到约 0.188。这有两种可能：
- **背熟了**：模型对训练窗口已经拟合得很好，dev 和 test 跟不上。继续用同样的数据训练没有用，要换数据或换正则化手段。
- **没学会**：训练窗口上的错误也和 dev 一样多。问题在学习率、训练方式或模型本身。

## 已知事实

每轮（12000 步，全局 batch 32，共 38.4 万个样本）里，真实会议训练数据被看的次数，按 E 组数据预检的配额算：

| 来源 | 训练记录数（两种声道视角各一份） | 每条每轮被看 |
| --- | --- | --- |
| AISHELL-4 | 20,710 × 2 | 1.82 次 |
| AliMeeting | 19,711 × 2 | 1.53 次 |

同一段音频还按 30 / 120 / 300 / 600 秒四种长度切窗、两种声道视角各出一份，所以每秒音频每轮被看的次数远多于每条记录被看的次数。

整条模型链（对话混合轮 → Emilia2 轮 → 第一轮）一直用 5e-6 学习率续训。

## 做法

- 模型：起点 Emilia2 6000 步（`/workspace/data/ae-runs/zh-emilia2-dialogue-6000/checkpoint-6000`）。
- 推理：部署推理栈 vLLM 0.18，`configs/serve-fit.yaml`。只把显存占比从 0.3 降到 0.22，因为本机 GPU 被其他会话占用。
- 评测：AmphionEval 0.10.0 meeting 评测器，打分口径与选模相同，`configs/eval-fit-start.yaml`。
- 数据：`configs/data/train-fit.yaml`，选的是训练用的同一登记版本 `real-meetings-v2-20261010` 的 `train_120s`。AliMeeting 和 AISHELL-4 各按种子 42 抽 150 条。这是训练集诊断，不是评测集，所以不跑全量（各约 4,000 条）。打分后剔除训练时排除的窗口（`zh-v2-train-excluded-records.txt`）。
- 对照：起点模型在 AliMeeting dev（138 条，20.42）、AliMeeting test（120 条，21.10）、AISHELL-4 test（120 条，23.55）上的结果，都是不计复读 cpER，同一模板、同一 AmphionEval 版本。

## 判断方法

- 训练窗口 cpER 明显低于 dev / test（例如差 5 点以上）→ 背熟了。
- 两者接近（差 1–2 点以内）→ 没学会。
- 介于两者之间时，再看归错和重叠句字错分别差多少。

## 结果

起点 Emilia2 6000 步，不计复读 cpER（%），各项都没有复读：

| 窗口 | 训过没有 | AliMeeting | AISHELL-4 |
| --- | --- | --- | --- |
| 训练窗口（抽样，去掉留出与空目标窗口） | 训过 | **7.48**（143 条） | **6.08**（126 条） |
| 留出的 18 场训练集会议（全部 120 秒窗口） | 10-08 起没再训过（更早的起点 LoRA 8000 训过，见 docs/experiments/2026-10-08）；房间都训过；AliMeeting 22 人中 16 人训过 | 23.74（123 条） | 18.42（205 条） |
| 官方 dev / test | 内容和说话人都没训过 | dev 20.42、test 21.10 | test 23.55 |

**结论：模型已经背熟训练窗口，而且只背住了内容。**
- 同一批房间、大部分是同一批人，只要内容在最近几轮没被反复训过，cpER 就回到 18–24，和完全没见过的 dev / test 一样。留出会议在 10-08 之前被最早的起点训过，现在照样回到没见过的水平，所以低错误率只出现在反复训过的内容上。
- 熟悉人和房间基本没帮助：AliMeeting 留出会议 23.7，比 test 的 21.1 还高；只有 AISHELL-4 留出会议比 test 低约 5 点。
- 这也解释了第一轮为什么原地打转：训练 loss 的下降来自继续背真实会议窗口，dev 和 test 学不到新东西。

**原因**：按 E 组配额算，每轮 12000 步里，每秒 AliMeeting 训练音频被听 11.2 遍，AISHELL-4 被听 12.9 遍。同一段音频切成 30 / 120 / 300 / 600 秒四种窗口，两种声道视角各一份，文字完全相同。前面几轮的配方类似，所以这些内容已经被听过几十遍。

**对下一步的含义**：
- 换切法（240 秒窗口、随机窗长、错开起点）改变的只是窗口边界，文字内容还是同一批，预计作用有限。
- 真正的瓶颈是真实会议的独特内容太少：AliMeeting 加 AISHELL-4 约 190 小时，被反复听了太多遍。
