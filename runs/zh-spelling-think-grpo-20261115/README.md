# 说字 think 的 GRPO（2026-11-15）

**状态**：2026-11-15 GRPO 完成，两个候选都没有满足全部判定；ACP 任务 `pt-uf80hisv` 已停止。同日用户接受 avg3 的小幅退步，avg3 进入交付评估，见"交付评估"。2026-11-16 交付评测发现鼎桥场景 TS 在“分开讲话”时会连另一个人一起转写（CER 3.35 → 9.24），正在定位（08）。

**要回答的问题**：说字 think 第二轮的 checkpoint-3000，think 开已经可用，说字也明显变强；但续训 SFT 把交付版 GRPO 压下来的误触发又冲了回去，和交付版做插值后 think 开又坏掉。照交付版的做法在它上面做一轮 GRPO，能不能同时做到下面两点？
- 守门回到交付版水平；
- think 开仍然可用，说字能力保住。

第二轮的结果见 `../zh-spelling-think-r2-20261115/README.md`。

## 设计

| | 交付版那一轮（oal-grpo 第十轮） | 本实验 |

- **剩下的差距在中文方言**（avg3 对交付版）：

- **插值版的守门都比 avg3 差**：插值的另一端是第二轮 checkpoint，它自己守门就差，插值等于往回退一半。交付版那一轮插值的另一端是 v9 插值，守门本来就好。
- **鼎桥普通识别，avg3 是 31.97**（交付版 18.39，差 +13.58 [−1.10, +44.36]，不显著），几乎全来自一条：

  - 第十轮的 v10 avg3 也在这一条出错（写出 89 字），见 oal-grpo `runs/amphionasr2-grpo-20261101/tasks/23-grpo-v10-from-v9interp/README.md`。
  - 其余是警务指令子集，错字数 94 → 98。
- **think 开**：
  - 上下文纠偏的 3,249 条 think 开输出全部正常闭合，没有空答案：avg3 有 2,064 条写说明、1,185 条写固定句，插值是 2,066 / 1,183。
  - 鼎桥机主识别 6 条中，avg3 有 1 条写了固定句后答案为空。其余 think 开项目与 think 关持平或更好。
- **没有再开实验**，原因如下：
  - 同配方再做一轮 GRPO：oal-grpo 第十一轮（从 v10 avg3 再做一轮）没有收益，只是在 TS 漏识别和误触发之间移动。
  - 与交付版插值：第二轮 50% 插值后 think 开已经坏了。守门大致随权重线性变化，think 还能用的权重下，中文方言仍会差于交付版。

#### 真实录音的泛化核对（2026-11-15）

合成子集与合成训练数据同源，泛化只看真实挖掘子集（127 条）。核对的是：这 127 条是不是训练里见过的内容。

- **录音不重叠**：127 条全部来自 WenetSpeech 播客，共 117 期节目。
  - 清洗时已把评测用过的 190 期整期去掉（见 `/workspace/workspace/mingdong/data/amphiondata/ctx-clean-zh-20261110/README.md`）。
  - 复核训练用的 `wenetspeech_clean@train-punc-v1-20261102-ctxclean-20261110`：37,129 期里与评测重叠 0 期。
- **内容不重叠**：同一档节目的主持人会在不同期重复同一句介绍，比如"微信搜索 XX，X 是 XX 的 X"。所以再按目标词和说明原文查。
  - 查的范围是训练里带说明的数据：WenetSpeech think 开记录的转写（923 条）、合成 train/train_ts 的参考文本（5,901 条），以及所有 think 文件里的说明引语（8,458 条）。
  - 目标词（两字以上）或说明原文（四字以上）出现过的，记为"见过"，有 38 条；两样都没出现过的有 89 条。
  - 脚本：`scripts/check_mined_overlap.py`。

  - 对照组 → avg3 think 开：没见过的 89 条新对 8、新错 0（p = 0.008）。

- 见过和没见过的两组涨幅相近，提升不是来自背题。
- 按说明方式（交付版 → avg3 think 开）：

  - 拆字 12 条：8 → 10；
  - 否定对比 6 条：3 → 6；

- avg3 think 开剩下的 21 条错误：
  - **think 写对、答案没照着写，8 条**。例如 think 写"写作「姿」"，答案仍是"小资"；think 写「开放的开」「语言的言」，答案是"开源英语"。

  - **标注存疑，3 条**：模型照说话人原话写，参考和说明对不上。
  - **没发现说明或漏写一处，2 条**。
  - **多处同音字、难词，2 条**。
- **局限**：
  - 场景只有播客，会议、电话、TS 场景没有真实说字测试集。
  - 127 条样本少，结论按条数报告。

## 三轮合起来的可复用结论（CoT ASR）

1. **think 是一种新的输入模式，训练要覆盖所有输入类型。**
   - 第一轮只在中文有声样本上开 think。think 开时中文 TS-ASR 测试集误触发 3.25 → 11.10，英文 WER 7.4 → 31.2。
   - 第二轮让空答案、其他语种、没扫描到的中文来源也以 3% 写固定句。守门各项 think 开与关的差都在 0.5 个点以内。
   - 代价很小：3000 步约 56 万条样本，其中写固定句的约 1.6 万条。
2. **think 写成短而固定的一行**："拼音 + 说话人原话 + 写作某字"，没有说明时写固定句。模型能分辨有没有说明：真实挖掘 127 条中 121 条写说明，6 条写固定句。
3. **收益来源排序**（真实挖掘答对条数）：
   - 清洗标注、上采样说明记录（第一轮对照组，没有 think）：87 → 98，新对 13、新错 2，是最大的一项；
   - 再加 think（第一轮）：98 → 102，新对 7、新错 3，不显著；
   - 再加合成说字数据（第二轮）：102 → 109，新对 8、新错 1。
4. **合成说字数据要配 think 才能迁移到真实录音。**
   - 加合成数据后，think 关 99 → 96，没有涨；think 开 102 → 109。
   - 同一 checkpoint，think 开比关多对 13 条，没有新错。
   - 条数少，只当方向性结论。
5. **带 think 的模型不能和没训过 think 的模型做权重插值。**
   - 第二轮插值 50% 后，think 那一行能写对，但不闭合 think，答案全空。
   - 平均只能在都会 think 的模型之间做，avg3 就是这样。
6. **GRPO 只用 think 关的采样，也能保住 think 开。**
   - 400 步、KL 0.04（参考模型为起点）之后，think 开在守门上仍与 think 关持平。
   - 真实挖掘 109 → 106，新错 3 条，不显著。
7. **在交付版上续训 SFT 会冲掉 GRPO 的收益，与 think 无关**，包括 GigaSpeech 误触发和方言。加新能力应走 SFT 之后再做一轮 GRPO 的流程。
8. **还没解决的两类错误**：
   - think 和答案不一致，占剩余错误的 4 成。GRPO 只奖励 think 关的答案，没有约束 think 开时答案要照 think 写。
   - 偏旁结构类说明基本没进步。

3. **不同说法推广得不一样。**

**think 里写了什么**（avg3 think 开；`scripts/ctx_v2_think_clue_target.py`，表在 `tasks/09-ctx-v2-eval/compare/think-clue-target.md`）

avg3 的 think 只有两种写法，都来自训练数据：
- 拼写模板“`<拼音>` 这个音，说话人说是「`<原话>`」，写作「`<字>`」”：只写一个音、一个字，不写要改转写里的哪个词。
- 隐式题几乎都写“这段没有说明字怎么写。”：独立组 192/200，同源 296/300。
- 训练用的 think 数据 `context_correction_synth_zh@train-v1-20261114` 有 5,901 条，全部是显式说明和同名一致性的单字拼写模板，没有隐式题，也没有多字目标。

对照评测集记录里的标准答案（`labels.context_correction.cot.edits`：线索 evidence、原词 from、改后 to），只看需要纠正的题：

| 独立组 | 纠正成功 | think 引用的话和标准线索对上 | think 写出了全部目标字 | 写出全部目标字时纠正成功 |
|---|---|---|---|---|
| 组词 | 75 | 99 | 87 | 86 |
| 否定对比 | 74 | 99 | 83 | 89 |
| 偏旁结构 | 42 | 96 | 37 | 95 |
| 拆字 | 19 | 98 | 18 | 83 |
| 逐字说明（每题 2 个以上目标字） | 29 | 99 | 1 | 100 |
| 隐式语义 | 29 | 2 | 0 | — |

“对上”指 think 引用的话和标准线索有连续 2 个以上的汉字相同。

- **显式说明的线索几乎都找到了。** 拆字、偏旁结构失败，是因为从线索推出的字错了：拆字有 81% 的题线索对了，目标字却一个都没写对。think 写对目标字时，最终输出基本跟着对。
- **逐字说明失败在模板。** 模板一次只写一个字，第二个目标字没有推理步骤。
- **隐式题没有推理步骤。** think 不写线索，也不写要改哪个词。
- **Emilia 隐式纠正变差，原因是模板被错用。** Emilia 上需要纠正的隐式题共 629 条：
  - 311 条 think 套了拼写模板，think 关 69.8、开 64.3；
  - 318 条写“没有说明”，think 关 64.5、开 65.1，基本不变。
- 同事反馈：在 CoT 里先定线索，再指明要改的目标，2B 的文本 LLM 能力也提升很大。这和上面的缺口对得上。
  - 训练和评测记录里都已经有“线索 + 原词 → 改后”的标准答案（训练集 `cot.edits`，1,487 条纠正题）。改 think 的格式不需要重新出题，但训练集里没有隐式题。
  - 拆字、偏旁结构是推字出错，不是没找到线索，光改 CoT 格式未必能解决。
