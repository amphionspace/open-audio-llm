# 12 GRPO 更新归因：为什么加负样本只挪门槛

## 结论

**目标缺席的提示给出的梯度，几乎不区分"这条该不该出字"，只是整体往"不出字"推。** 在起点 S（SFT 073 avg3，v23–v25 的共同起点）上，决策 token 的梯度让正样本的 margin 上升得和难负样本一样多。相似嗓音负样本是这样，v15 的普通负样本也是这样，各模块都是。所以再往训练里加负样本，不论加多少、选多像的，单步梯度能做的只有挪门槛。

| 起点 S，第 001 / 003 次（两个随机种子） | 难负样本 | 正样本 | 正 / 难 |
|---|---:|---:|---:|
| 相似嗓音缺席题，决策 token | 150 / 159 | 156 / 176 | 1.04 / 1.11 |
| v15 缺席题，决策 token | 175 / 167 | 174 / 172 | 0.99 / 1.03 |
| v15 在场题，决策 token | −161 / −164 | −209 / −224 | 1.30 / 1.36 |
| 相似嗓音缺席题，其余 token（转写文字等） | 4.0 / −1.2 | −13 / −4.3 | – |

数值是沿该梯度分量走单位步长时 margin 的一阶变化，取各组样本均值。margin = log p(None) − max(log p(Chinese), log p(English))，正值表示推向不出字。

- **转写文字 token 不是原因。** 误报的转写文字拿了几乎全部负梯度，但它对决策 margin 的作用只有决策 token 的约 5%。"压低转写让模型更不敢出字"这个假设不成立。
- **实际权重更新有区分，但区分落在易负样本上。** 用 v15、v23、v24、v25 avg3 减去 S 的实际更新（Adam 累积 400 步）。一阶预测与实际 margin 变化的相关系数为 0.95–0.99。实际 margin 变化如下：

| 实际更新（S → avg3） | 难负样本 | 易负样本 | 正样本 |
|---|---:|---:|---:|
| v15 | +2.6 | +4.2 | −2.9 |
| v23（同语料相似嗓音 ×15） | +4.2 | +5.3 | −1.0 |
| v24（半数在线相似嗓音） | +3.1 | +4.2 | −1.0 |
| v25（挖掘的相似嗓音计划） | +4.8 | +6.0 | −1.5 |

  - 每一轮都是易负样本动得比难负样本多：GRPO 改进的是本来就容易判对的样本。
  - v25 相对 v15 多出来的部分是难负样本 +2.1、易负样本 +1.8、正样本 +1.4，约三分之二是整体平移。这和评测上"误报降、漏识升"一致。
  - v23、v24 多出来的部分推正样本（+1.9、+1.8）比推难负样本（+1.6、+0.4）还多，所以更差。
- **编码器基本没被训练动到。** 实际更新带来的区分主要在 LLM 第 10–19 层（v25：难负样本 +1.6、正样本 −0.7），其次是第 0–9 层。音频编码器各层段的贡献都在 ±0.3 以内。任务 09 已经确认误报的根子在说话人表示（编码器层 24 的余弦能区分、外部 ECAPA 不能）。GRPO 的 presence 信号几乎到不了编码器，这一点和"只挪门槛"相互印证。
- **起点越好，梯度越有区分（第 002 / 004 次）。** 从"两轮相加"出发，相似嗓音缺席题决策 token 的比值降到 0.79 / 0.82，v15 缺席题为 0.95 / 0.97；v17、v18 实际更新分别为 0.40 和 0.19 / 0.17。但它们同样推高了正样本的 margin（+0.67、+0.48），对应评测上用漏识换误报。

**推论：** 继续调 GRPO 的数据配比或负样本难度，解决不了"像目标的人也出字"，问题在训练信号够不着的地方。要同时降误报和漏识，需要直接作用于说话人表示的训练信号。例如对编码器做对比学习：同一注册段，配同人片段和相似嗓音片段。或者在同一组里成对放"同一混合段换注册"的在场 / 缺席题，让整体平移的分量互相抵消。

## 方法（`scripts/grad_attribution.py`、`scripts/analyze_attribution.py`）

1. **rollout**：按 `train-data-grpo-v25.yaml` 的 `GRPOPromptPlan` 渲染提示，和训练看到的音频完全相同。三类提示各取 64 条：v25 相似嗓音缺席计划、v15 缺席计划、v15 在场计划。
   - 每条用起点模型采样 8 次（HF generate，温度 1）。
   - 用训练的奖励函数和权重打分（accuracy 1、presence 1、hotword 1、format 0.25），套用 presence contrast，按组 z-score 得到优势（ms-swift `scale_rewards: group`）。
2. **梯度分量**：起点处一步 GRPO 是 on-policy 的（比值为 1，KL 梯度为 0），上升方向为 Σ_i A_i/L_i Σ_t ∇log p(token_t)（`loss_type: grpo`，每条序列按 token 求平均）。
   - 按提示类型 × token 部分分别累加。决策 token 指语言名，即 ` None` 还是某种语言；其余 token 包括 `language`、`<asr_text>`、转写文字和结束符。
   - 冻结参数与训练一致：embed_tokens 和音频卷积层。
3. **留出**：起点模型的 v12 评测样本，18 个家族各 40 条，共 720 条。
   - 难负样本：short-hard、abs-hard、abs-hard-k1、realreg3-hard、enroll-short1-neg、enroll-contam0-neg。
   - 易负样本：short-rand、abs-rand-k1、abs-k2、enroll-clean-neg。
   - 正样本：short-k1、dyn-full/burst/overlap-k1、dyn-alternate-k2、enroll-clean/short1/contam0-pos。
   - 每条求 margin 的梯度，与各分量（单位化）以及实际更新做点积，并按模块分组。另外直接前向计算实际 checkpoint 的 margin，用来核对一阶近似。
4. **局限**：
   - 原始梯度没有经过 Adam 的逐坐标缩放，所以结论以实际更新为准，原始梯度只用来判断单步信号的方向。
   - 每类 64 条提示、单步；换随机种子（003、004）后结论不变。
   - 联合 MTP 损失（权重 0.1）没有计入。
