# 08 `None` 偏置的工作曲线：后续 GRPO 是否只是在挪门槛

- 输入：whitebox-merge-sum-full 在 ts-asr-benchmark v12 上的决策位置状态（`scripts/extract_states.py`，首 token 与 vLLM 一致 99.87%）；`scripts/none_bias_curve.py` 给 ` None` 加固定 logit 偏置 b，只看"出不出字"这一步。
- 口径差：b=0 时本脚本数出误出字 465、漏识别 2.31%；AmphionEval 的同一模型是 453 / 2.50%（漏识别按整条空输出计、样本集略不同），比较时按约 +0.2 个百分点的漏识别偏差看。

| 模型（AmphionEval） | 误出字 | 漏识别 | 两轮相加加偏置、误出字相同时的漏识别（曲线，已加 0.2） |
|---|---:|---:|---:|
| v17 avg3 | 350 | 3.13% | 约 3.2%（b≈+1.0） |
| v17/v18 各半 | 308 | 3.23% | 约 3.6%（b≈+1.5） |
| v18 第 400 步 | 274 | 3.44% | 约 4.1%（b≈+2.0） |
| v17+v18 全量 | 228 | 4.48% | 约 4.9%（b≈+2.75） |

结论：v17 基本落在偏置曲线上（只挪了门槛）；v18 与两分支合并在同样的误出字下漏识别少 0.4–0.7 个百分点，学到了偏置给不了的东西，但总错误率仍高于两轮相加本身，因为漏掉整句的代价更大。只想少出错字时，给两轮相加加偏置是零训练的选项。
