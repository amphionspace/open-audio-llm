# 10 外部说话人嵌入（ECAPA）能否补上模型的"在场/不在场"判断

## 结论

**不值得为降误出字专门接入外部说话人嵌入。** 在 v12 所有成对的 pos/neg 集合上，ECAPA 验证分区分"目标在场/不在场"都明显弱于模型自己的决策 margin；两者做逻辑回归组合后，与只用 margin 几乎一样（难集合并 AUC 0.980 vs 0.980）。按"正样本最多损失 0.5%"的门槛做后置门控，组合分去掉 74/452 条误出字，只用 margin 是 73 条；热点 208 条里分别是 20 和 15 条。first-other v3 上用 ECAPA 做全局门控也只能去掉 0–4/106 条。

唯一的例外是 first-other 的 `control-aishell4-ef-mf`（25 条误出字）：ECAPA AUC 0.985，只用这个集合自己调的阈值能去掉 17/25 条、只损失 1 条正样本。但这个阈值（0.42）明显高于全局阈值（0.20），换成全局阈值后就基本去不掉了，所以只算一个局部现象，不足以支撑接入。

## 方法

- 模型：whitebox-merge-sum-full（两轮相加）。v12 run `run-20261107T054755Z-b3a6683a`，first-other v3 run `run-20261107T061511Z-6fd61563`。
- ECAPA 分：WeSpeaker ECAPA-TDNN512-LM（本地 ONNX，CPU）。注册按服务约定裁剪/补零到 5 s，只保留能量 VAD 判为有声的部分；混合段按 1.5 s 窗、0.5 s 步长滑动，保留有声帧 ≥50% 的窗，取注册与各窗余弦的最大值。不用 metadata 里的说话人时间段（真实部署拿不到）。
- 模型 margin：`states-sumfull-v12.npz` 最后一层 logit lens，`logp(None) − max(logp(Chinese), logp(English))`，取负号使"越大越像在场"。
- 组合：标准化后的 [ECAPA 分, −margin（截断到 ±30 nat）] 做逻辑回归，按集合基名（去掉 `-pos/-neg`）分组 10 折交叉验证，每条样本的组合分都来自没见过它所在集合的模型。
- 家族：同名 `X-pos/X-neg` 自动配对；另外人工配对 `abs-hard-k1 / abs-rand-k1` 对 `dyn-{full,burst,overlap,short}-k1`，`abs-hard / abs-k2` 对 `dyn-{alternate,burst,enter,leave}-k2`，`realreg3-{hard,mid2,}-neg` 对全部 `real-*-pos`，`short-{hard,rand}-neg` 对 `short-k1-pos`。
- 客户 TS（`ts-2026*`，49 条）不纳入统计，所以 v12 误出字总数为 452（含客户集是 453）。

## 2. 只看模型判错的样本

ECAPA 阈值取 enroll-clean pos/neg 上的 EER 点（阈值 0.330，EER 18%）。

| 范围 | 模型错的条数 | ECAPA 判对 | 作为对照：模型判对的样本里 ECAPA 也判对 |
|---|---:|---:|---:|
| v12 全部误出字 | 452 | 271（60%） | 20,866 / 25,925（80%） |
| v12 全部漏识 | 324 | 114（35%） | 同上 |
| v12 热点误出字 | 208 | 135（65%） | 1,311 / 1,632（80%） |
| first-other 误出字 | 106 | 42（40%） | 7,101 / 8,849（80%） |
| first-other 漏识 | 75 | 57（76%） | 同上 |

在模型判错的样本上，ECAPA 的正确率反而比它的平均正确率（80%）低。也就是说，ECAPA 和模型的错误不是互补的；ECAPA 能"救回"的那些样本，代价是在模型本来判对的样本上犯更多错。

## 3. 后置门控的收益上限

模型已经出字时，如果分数低于阈值就改成空输出。阈值取"损失的正样本 ≤ 全部正样本的 0.5%"（v12 是 64 条，共 12,950 条正样本）。

| 门控分数 | 损失正样本 | 去掉误出字（共 452） | 去掉热点误出字（共 208） |
|---|---:|---:|---:|
| 模型 margin（相当于加 None 偏置） | 53 | 73 | 15 |
| ECAPA | 64 | 24 | 9 |
| 编码器层 24 余弦 | 64 | 11 | 2 |
| 组合（交叉验证） | 64 | **74** | **20** |

预算放宽到 1% 时：margin 去掉 118/30，组合去掉 120/32（全部/热点）。组合比 margin 多出来的只有 1–5 条。

**first-other v3**（9,030 条：5,004 正，4,026 负；模型误出字 106，漏识 75；没有 states，只用 ECAPA 加模型的空/非空输出）：

| 阈值来源 | 损失正样本 | 去掉误出字（共 106） |
|---|---:|---:|
| first-other 自身调阈值，正样本损失 ≤0.5% | 25 | 4 |
| first-other 自身调阈值，≤1% | 50 | 8 |
| 直接用 v12 的 ECAPA 阈值（0.090） | 2 | 0 |
| 只在 `control-aishell4-ef-mf` 调阈值（0.418） | 1 | 17 / 25 |

ECAPA 在 first-other 全集上 AUC 0.900。模型的硬判决（空/非空）等价 AUC 是 0.979，这是二值判决的值，和连续分数的 AUC 不能直接比。

## 4. 对改进方向的含义

- 09 的发现是："约一半误出字来自声音相近的干扰者，ECAPA 并不觉得它们特别像"。这个现象是对的，但放到逐条判断上，ECAPA 自己的验证分误差更大（难集上 AUC 0.59–0.80），模型的 margin 已经达到 0.93–0.99。外部嵌入**没有提供模型缺少的、能用于决策的信息**。
- 所以"接入说话人嵌入"在降误出字上的预期收益有限。误出字更现实的处理方向是 08 的偏置/门槛和训练数据（难负样本、短注册、被污染的注册）。
- 局部例外：first-other 的 aishell4 control 集里，ECAPA 有模型没用上的信息（单集调阈值能去掉 2/3 误出字）。如果后续只想处理这个场景，可以先查这个集合的构造（远场注册、远场混合段），不要据此接入全局嵌入。

## 证据与限制

- 数字：`ecapa-check.json`；逐条分数：`scores-v12.jsonl`、`scores-firstother-v3.jsonl`（本地，含客户集 id，不外传）；日志：`score-*.log`。
- 脚本：`../../scripts/ecapa_check/score.py`（ECAPA 打分，40 进程 CPU，v12 约 20 min）、`../../scripts/ecapa_check/analyze.py`（AUC、交叉验证组合、EER、门控）。margin 和层 24 余弦从 `../08-none-bias/states-sumfull-v12.npz` 读取（`lens_logprob[:,28]`、`audio_{enroll,mix}_mean[:,24]`）。HF 与 vLLM 的首 token 有 36 条不一致（都是近平手），没有排除。
- ECAPA 这里只做了不分离说话人的滑窗验证，是最简单的外部打分。分离或说话人分割之后再验证可能更强；但 09 用 metadata 真实说话人时间段截干扰者，难集组内 AUC 也只有 0.38–0.80，所以更强的打分也很难追上 margin。
- 这里只检验了**后期融合**（模型外部组合分数）。训练时把嵌入注入模型，让模型学着用它，理论上可能得到不同的结果；离线检查无法排除这种可能。但现有证据说明，外部嵌入在这些条件下包含的说话人信息比模型自身少，所以不支持优先投入。
- 门控阈值是在被评估的同一集合上按正样本预算选的，属于上限估计（first-other 换成 v12 阈值后收益基本为 0）。
