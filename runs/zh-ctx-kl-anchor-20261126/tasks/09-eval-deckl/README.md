- **按写定的分支“1 不成立，判断 token KL 没有降低”：查这一项为什么没起作用（实现、梯度量级），不重跑。**
  - **实现没有写错**：
    - 和后续 1 的代码差别只有判断项；两臂的生效配置也只差 `decision_kl_weight: 1.0`。
    - 第 1 步和后续 1 是同一个 batch，CE、token 平均 KL 都相同，判断 token KL 只有数值差、不为 0。
    - “第 1 个监督 token 是 `language`、每个样本恰有一个判断 token”的断言在整个训练中都没触发。
  - **梯度量级不是太小，而是太大、太集中**：
    - 裁剪前的梯度范数在最后 10% 从 5.6 升到 12.2（臂 A）、从 4.2 升到 9.8（臂 B）。阈值是 1.0，每步都被裁剪，所以判断项占了每一步更新的大头。
    - 相对 11.17 的权重改动在每组模块上都比后续 1 小约 5%（`weight-delta.log`）。判断项改的是更新方向，不是更新幅度。
    - 开发机 CPU 逐条量梯度（`scripts/decision_grad_coherence.py`，日志 `grad-coherence-kltreal.log`）。学生用后续 1 的 kltreal-1557（还没加过判断项），老师用 11.17，冻结部分和训练相同，从回放采样器取 TS 负样本、TS 正样本各 24 条：

      | | TS 负样本：判断 token | TS 负样本：整句平均 | TS 正样本：判断 token | TS 正样本：整句平均 |
      |---|---|---|---|---|
      | KL 均值 | 0.0071 | 0.0142 | 0.0097 | 0.0124 |
      | 梯度范数：均值 / 中位数 / 最大 | 6.5 / 4.8 / 35.6 | 5.6 / 4.7 / 11.9 | 10.8 / 1.8 / 35.6 | 4.3 / 4.2 / 8.5 |
      | 样本之间梯度的平均两两余弦 | 0.019 | 0.0006 | 0.051 | 0.0004 |
      | 陡度 \|g\|²/(2·KL)，KL > 0.005 的样本中位数 | 4,254 | 1,077 | 8,834 | 732 |

      - 每条样本的判断梯度和整句梯度的余弦：正样本 0.117，负样本 0.069。也就是说，判断项给的是一个基本独立的新方向。
    - **怎么读**：
      - **陡**：在 KL 不小的样本上，判断 token 的方向比整句平均陡 4–12 倍；梯度范数是重尾的，正样本中位数 1.8，最大 35.6。
      - **单步里噪声占主导**：样本之间平均两两余弦为 ρ 时，N 个样本平均梯度里的共同方向要到 N ≈ 1/ρ 才压过噪声，也就是 TS 负样本约 50 条、正样本约 20 条。训练每步只有 4 个回放样本，TS 负样本占 13.5%，平均每步不到 1 条。
      - **结果**：每步实际上沿着一两个样本的判断梯度走，而且在最陡的方向上走。裁剪后的步长由学习率定，峰值学习率时这一步就迈过头，其他样本的判断 KL 被推高。
    - **和训练、评测的现象对得上**：
      - 两臂和后续 1 正好在 warmup 升到峰值学习率那一段分开（第 100–250 步、第 100–480 步）；
      - 学习率下降以后判断 KL 回落（臂 A 中段 0.038 → 最后 10% 0.024）；
      - 评测上每臂的门槛整体移动一次，方向各不相同，幅度比整个纠偏 SFT 带来的还大。
  - **结论**：
    - 在每步 4 个回放样本的 batch 里，对判断 token 单独加一项 KL 拉不住在场判断，反而会注入噪声。
    - 问题不在权重 1.0：换权重只是放大或缩小同样的噪声，所以按分支不重跑、不扫权重。
    - 能解决根因的设计是每步给判断项足够多的样本（按上面的 ρ，几十条 TS 样本），让它的梯度方向稳定。这是新的设计，要先写定判定再训练，留给用户决定是否继续。
    - 以上是和全部证据一致的解释，没有用重跑证明。
