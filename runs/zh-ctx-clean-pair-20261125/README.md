### TS 回退的原因：差值里大部分是两次训练各自的随机走向，不是说字清洗

**静态核查一：清洗改了 TS 来源的多少条**（`context_correction_clean_zh@v1-20261110` 的 state.json）。
- TS 来源里改字、隔离的条数都极少：
  - emilia2_dialog 76 万条里改 38、隔离 181；
  - emilia2_mix 177 万条里改 68、隔离 411；
  - aishell4 / magicdata 的 TS 切分合计改 1、隔离 6。
- 唯一成规模的差别是说明记录上采样（约占样本 1.10%，都是有文字的正样本）。
- 这些都不足以让英文、西语 TS 的误触发涨 1.3–1.9 点。

**静态核查二：权重增量的大小和方向**（`scripts/delta_norms.py`，输出 `tasks/02-delta-norms/`）。

| 增量 | 范数 |
|---|---|
| 对照组 − 11.06 | 5.26 |
| noclean − 11.06 | 5.23 |
| **对照组 − noclean（pm-clean 加上去的）** | **6.82** |
| G − 对照组（pm-real 加上去的） | 4.00 |
| J − G / H − G（之前两次合并） | 6.72 / 6.56 |
| 11.17 − 11.06 | 14.04 |

- 两次训练从同一起点出发，配置只差约 1% 的数据，但增量几乎正交（余弦 0.155）。
  - 数据配置一变，整个采样顺序就变了，3000 步后两条轨迹各走各的。
- 所以“对照组 − noclean”比任何一次训练自己的增量都大，主体是两次训练各自的随机走向，说字清洗的信号只占一小部分。
- 把它加到 11.17 上，等于“加一次训练、再倒扣一次训练”。推测倒扣的那部分是 TS、ASR 回退的主因（误触发、CHiME-4 漏识别都上升），这一点没有单独验证。
- pm-real 的增量小（4.00），TS 只差 0.2–0.6；pm-clean 的增量大（6.82），TS 差 1–2 点。方向一致。

**对之前结论的修正**：之前用差值合并得出的“每块合成数据都有 TS 代价”也混着这种随机走向（J − G、H − G 的增量同样大），不能全算在数据头上。数据本身的 TS 代价要在同一起点上直接比，而且两次独立训练之间约有 0.4 的波动。

### 结论

- 真实录音上的纠偏收益确实来自说字清洗数据（在 11.06 上 +1.6\*，只续训 +0.1）。
- 用差值合并把它单独加到 11.17 上走不通：差值主要是训练随机性，TS 回退远超收益。这条路记录后不再做。
- pm-clean 不是候选，11.17 不变。
- 剩下要回答的：说字清洗放进 SFT 本身有没有 TS 代价。这决定能不能建议主线下一轮 SFT 用说字清洗版本、放在 GRPO 之前。见下一节。

| 项目 | 11.06 | noclean | 对照组 | G |

**读法**：
- **只是阈值位置不同，总错误不更差**。对照组对 noclean：
  - v12 误触发 +1.25\*、漏识别 −1.47\*，两项和 6.75 → 6.54，CER 14.51 → 13.32\*，更好；
  - 跟错人两项和 4.32 → 4.84，CER 持平（+0.04，不显著）；
  - 英文 TS 误触发、漏识别、WER 都更好。
- **偏离的是 noclean，不是对照组**。和 11.06 比：
  - noclean 的 v12 漏识别 +1.68\*、误触发 −0.91\*，英文 TS 漏识别 +1.18\*，跨语种漏识别 +6～8\*，CHiME-4 漏识别反而 4.02 → 0.76；
  - 对照组和 G 互相很接近（v12 各项差 ≤ 0.12）。
- **之前的噪声估计偏小**。noclean 和对照组只差约 1% 的数据，权重走向却几乎正交，TS 阈值位置差 1–1.7 点。“两次独立训练约差 0.4”是只看跟错人漏识别得出的，对阈值位置来说偏小。这一对模型里，说字清洗自己的 TS 作用和训练随机性分不开。
- **续训本身的代价照旧**：三个续训模型的 v12 两项和（6.48–6.75）都比 11.06（5.99）差，CER 也都更差。这和 11-23 的根因（在 GRPO 模型上续训）一致，与说字清洗无关。
- **说明记录上采样那 1.10%**（分支要求查）：
  - 其中约 42% 是有目标人说话的 TS 正样本（emilia2_mix 2/3 人、emilia2_dialog），约占全部样本 0.46%；
  - 方向上和“对照组多出字”一致，但量级上很难解释 1.25 点。没有单独验证。

**结论**：
- 说字清洗数据带来真实录音收益：在没见过的真实题上，含它的五个 11.06 系模型（对照组、G、H、template、J）+1.0～+2.2，不含的 noclean +0.1。
- 在 SFT 层面没有看到它让 TS 的总错误变差，只看到阈值位置不同，而这一差别在训练随机性范围内。
- 阈值位置由之后的 GRPO 重新定（11-22 配方对照：GRPO 只沿曲线挪阈值）。
- **建议**主线下一轮 SFT 换用说字清洗版本，放在 GRPO 之前，不在 GRPO 模型上续训；做不做由用户决定。
  - 需要守住的是 GRPO 之后的 TS 全表，不是 SFT 模型的误触发。
  - 主线若做，最好配一个不含说字清洗、其余相同的对照，并且看 TS 时以总错误为准。
