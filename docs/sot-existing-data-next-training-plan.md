# 下一轮 SOT 训练：复用现有数据，补长对话、更多说话人和中英切换

制定日期：2026-09-21。状态：计划已制定，数据转换和新合成尚未执行，未启动新训练或切换当前运行。

目标：用已有语料改善连续会议中的转写、说话人归属和时间戳，重点覆盖 2～10 分钟、多人再次发言、句内中英切换及远场声学。直接安排一次 60,000 步正式训练，不安排试训；encoder、aligner、LLM 全部更新。普通 ASR 继续由既有目标优化，其退化不设为阻断或早停门槛。

## 2. 固定训练配比

以下均为样本抽样权重，总和 100%；不是音频小时比例。全程使用同一配方，方便解释 checkpoint 变化；同时记录实际样本、音频秒数、监督 token 和重复采样次数。

| 训练来源 | 样本占比 |
|---|---:|
| AISHELL-4 长会议 SOT | 15% |
| AliMeeting 长会议 SOT | 15% |
| RAMC 连续对话 SOT | 10% |
| AMI 长会议 SOT | 8% |
| NOTSOFAR 会议 SOT | 7% |
| CHiME-6 会话 SOT | 5% |
| 旧时间戳合成 SOT | 5% |
| 新词级轮次合成 SOT | 15% |
| TALCS 中英混合句 ASR | 7% |
| CS-Dialogue mix ASR | 3% |
| 中文普通 ASR | 7% |
| 英文普通 ASR | 3% |

合计：真实会话 60%、合成 SOT 20%、中英切换 ASR 10%、普通 ASR 10%。相较当前真实会议 40%、旧合成 40%、普通 ASR 20%，主要变化是增加真实会话种类和权重，并将中英切换独立采样。这些是本项目的实验选择，不是论文公开配比。

中文普通 ASR 内部固定为 `wenetspeech_clean@clean-v3-20260828` 5%、`aishell@icefall-20260908` 1%、`kespeech@icefall-20260908` 1%；英文为 `commonvoice_en_clean@clean-v1-20260805` 1.5%、`librispeech@icefall-20260908` 1.5%。LibriSpeech 保留现有 train-clean-100/360 选择。已有 clean 来源继续 `require_clean_pass: true`。其余来源未找到适用的正式 clean 训练版本，使用固定现有版本；文件名中的 `cleaned` 不等于可伪造 clean-pass 标记。

TALCS 的 7% 来自同时包含中文和英文的训练句子，实际可选小时数在准备时统计，不将全部 555.93 小时标成 code-switching。CS-Dialogue 使用现有 mix 入口，不再叠加同源全量／热词／加噪版本来扩大数据量。两者首先使用原文 ASR 目标；混合语言句进入 SOT 合成前，须有可靠对齐和说话人来源。

## 3. 真实长会话准备

复用 AmphionData 的 `multispeaker/meetings.py`，新增 RAMC、AMI、NOTSOFAR 和 CHiME-6 适配，不改写原音频和人工文本。现有脚本只处理 AISHELL-4、AliMeeting，且假定 `legacy_asr` 根目录；RAMC 位于 `multilingual`，CHiME-6 使用 AudioRecord，均需要实际接入后才能发布新版本。

目标窗口 30／120／300／600 秒，采样权重 **10%／20%／40%／30%**。这里是目标窗口，较短原会话保持原长，不补零或循环音频凑时长。按原会话连续切分，保留停顿、插话、重叠和长间隔后再发言；同一窗口内 speaker ID 固定，按首次出现编号。不同窗口不宣称全会议 speaker ID 已完成关联。

边界落在发言／重叠簇之间，不截断原文。沿用 650 秒音频上限与 16,384 总 token 预算；预算计算同时包含音频 token、提示和完整目标。超预算训练窗口先尝试在合法边界缩短；不可分窗口记录排除原因，不截掉目标尾部。开发／测试不按难度或 token 长度静默筛除。

新语料的通道策略：AMI 使用既有 SDM；NOTSOFAR 按官方 meeting ID 归并设备视图，先抽会话再抽一个可用设备；CHiME-6 每个样本选择一个与标注时间轴核对过的远场通道，不平均未经验证同步的跨设备通道。AISHELL-4、AliMeeting 保留本轮既有通道策略，以减少同时变化的因素。

CHiME-6 已发布视图有 37 条排除标注，其中有的只是超出其他较短通道。准备时将排除清单与所选通道、窗口求交：原标注在所选通道有效则保留；无法保证完整转写的训练窗口明确排除，不能让可听见的话变成无标签背景。开发／测试保留原始标注与限制说明。

派生版本拟用 `meeting-long-v2-existing-20260921`，发布时冻结源版本、转换参数、清单 SHA256、代码版本与原会话映射。该名称目前只是计划，尚未登记为可用数据。

## 4. 新合成：补人数和轮次结构

保留旧版 `synthetic-v2-timed-trial-v1-20260920` 及当前恢复后的 alignment index，作为 5% 短音频锚点。新增合成目标 **50,000 条通过检查的训练样本**，使用本地现有单人来源和真实中英混合句；不下载新语料、不用无转写的说话人分类数据凑 SOT 文本。

新合成的初始采样参数如下，均是拟定值：

| 维度 | 分布 |
|---|---|
| 目标长度 30／120／300／600 秒 | 10%／35%／40%／15% |
| 总说话人数 2～4／5～8／9～12 | 50%／40%／10% |
| 中文／英文／含真实句内中英切换 | 50%／25%／25% |
| none／low／medium／high／dense 重叠档 | 25%／35%／25%／10%／5% |

词级切分复用现有原始强制对齐结果；当前 SQLite 索引只保存句子边界，需接入原始词级信息。切为连续词段，尽量在低能量位置切分并短淡化，完整保留被选词段的文本。长度、停顿、轮次和发言占比参考真实训练会话统计；生成接话、打断、长暂停和同一人多次返回，区分参会人数与同时发言人数。

TALCS／CS-Dialogue 保留同一个人的真实混合语言句；不同单语说话人轮流说中英文不计为句内切换。TALCS 的 speaker ID 映射需在用于混合前核对，不能仅凭文件名前缀推断真实身份。对齐失败时不伪造时间戳，记录失败并从同一目标桶补采样。

拟定增强分布：原声 40%、仅噪声 25%、仅 RIR 20%、噪声与 RIR 15%。加噪样本中 80% 的 SNR 均匀取 5～20 dB，20% 取 0～5 dB；先以未加噪的有效语音能量确定 SNR。只用 MUSAN noise，避免混入缺少转写的可懂人声。

RIR 在每个说话人干净轨道上处理，保持同一场景房间／麦克风条件和同一说话人的位置一致，随后混音。裁剪／卷积延迟必须映射到目标时间轴，不能简单打开当前在线 RIR 开关后保留旧标签。用已知边界音频验证延迟映射，核对最终混音无丢词／截断；真实远场数据首轮保持原声，避免额外混响掩盖来源差异。时间戳样本继续禁用未同步修改标签的变速。

派生版本拟用 `synthetic-v3-wordturns-20260921`，冻结随机种子、原始片段、说话人、词边界、偏移与增强参数。50,000 条按上述目标长度粗算约 3,542 小时输出、约 408 GB PCM 等效体量；这是生成规模估算，实际长度、FLAC 空间和上下文拒绝率另记，不把它当作新增独立真实语音。

## 5. 去重与固定评测隔离

1. 原始语料只选一个固定入口；legacy、runtime、热词、加噪、replay 不作为互相独立的数据集累计。
2. 按源 recording／meeting ID 处理 split 隔离。NOTSOFAR 同会话不同设备归为同一组；CHiME-6 的片段和完整会议只通过完整会议派生入口消费。不同长度窗口是允许的训练视图，但不增加独立语料小时数。
3. 新合成仅使用官方训练来源，并沿用旧合成的 held-out speaker 排除名单，防止旧合成开发集来源被重新加入训练。source speaker ID 加数据集命名空间，不把两个语料的同名 ID 当作同一个人。
4. 对来源映射冲突／疑似别名副本比较文件哈希或规范化音频指纹；无需为没有证据的跨库近似重复先构建大规模检索系统。训练与评测的实际冲突只从训练侧排除，固定评测不改标注、不删难例。报告检查范围，不声称全库内容级零重复。

## 6. 正式训练参数与初始化

| 参数 | 计划 |
|---|---|
| 模型架构／原始 base | Qwen3-ASR-1.7B |
| student 初始化 | 切换时当前会议恢复运行的最新完整 checkpoint，固定具体路径、step 与权重哈希 |
| teacher | 现有原始 Qwen3-ASR-1.7B，冻结 |
| 更新模块 | encoder、aligner、LLM 全量 |
| 正式预算 | 新运行 60,000 optimizer steps；不是从旧 step 续到 60,000 |
| optimizer／scheduler | 新建 AdamW fused、cosine；不恢复旧动量和旧数据采样游标 |
| encoder／aligner／LLM 峰值 LR | `1e-5 / 2e-5 / 1e-5` |
| warmup／weight decay／grad clip | 500 步／0.01／1.0 |
| 精度／显存措施 | FP32 主参数、BF16 autocast、gradient checkpointing、现有分块 CE、expandable segments |
| GPU／梯度累积 | 2 × A800 80GB／4 |
| 动态组批 | 沿用最多 4 条、650 秒音频预算、8 个桶；完整上下文不超过 16,384 tokens |
| 目标函数 | 现有 sample-mean CE；普通 ASR（含中英切换）沿用 teacher KL 权重 2 |
| 保存 | 每 500 步保存完整恢复状态；保留最近 3 份，并单独保留起点、评测中的模型、最佳模型和最终模型 |

先做初始化模型的固定 dev 基线，再进行正式训练；这不是试训。此前 4 条样例中 checkpoint-2500 最好，但不足以据此回退起点或认定全局最优。实际起点在切换时冻结，不能在后台轮转过程中丢失。

当前旧配方实测约 8.56 秒／步，60,000 步约 143 小时、6 天，仅作资源量级参考。新配方增加长会话，按正式训练前 1,000 步实测吞吐更新预计完成时间，不承诺沿用该速度。

## 7. 评测与选点

保留当前 4 条诊断样例用于回看，但不再用它们选全局最佳模型。准备固定 dev 面板：六个真实会话来源各 8 条，共 48 条，尽量覆盖 30／120／300／600 秒、人数和重叠条件，缺少某时长的来源按实际分布选取并记录；另取 TALCS、CS-Dialogue mix 各 16 条固定 dev，共 32 条中英切换 ASR。片段 ID、原文、时段和抽样种子在训练前冻结，不因模型表现重新抽样。

每 2,500 步评测固定面板；同一初始化模型与候选最终模型再比较覆盖完整官方 dev 的窗口集合，最后对选定模型评一次官方 test。长会话采用固定的约 600 秒窗口，沿用发言边界切分以避免参考文本被截断，切分不随 checkpoint 改变。不可分的超上限窗口仍保留并报告失败／覆盖率，不静默删除。评分标记为逐窗匹配说话人；这是使用参考边界的窗口级协议，不冒充官方整场全局匹配成绩，也不声称衡量了跨窗口身份保持能力。

中文会议主报 tcpCER，英文会议主报 tcpWER，主 collar 固定 5 秒，并附 1 秒诊断。优先使用源词时间戳；只有句级边界时明确记录字符／词时间为评分器估计。所有 checkpoint 使用同一规范化、分词、解码和时间参数。与旧 4 条分数比较时另保留原协议，不能直接比较更换预算后的数字。

并报 cpCER／cpWER、说话人数正确率、DER（0.25 秒 collar，计入重叠）、句级边界 F1／MAE、格式有效率、输出触顶率和漏词率。中英切换 ASR 单独报统一规范化的 CER 与英文词错误率；这些 ASR 样本没有原始多人时间轴，不伪报会议 tcpWER。

greedy 解码，`max_new_tokens = min(8192, 16384 - 实际输入token数)`；输入计入完整音频与模板，输出预算包含终止 token，具体计数由运行模板计算。该上限替代旧诊断统一 2048 的配置，所有待比较模型一致。仍触顶的样本保留并评分，不能丢弃或仅对某个 checkpoint 增加预算。解析失败保留原始文本，记为失败；评分器若无法计分，明确报告覆盖率，禁止用成功子集包装成全量分数。

选点先按三个中文真实会话 dev 的宏平均 tcpCER 最低；英文会议 tcpWER、中英切换 ASR 和长音频／多人分桶作为独立结果展示，不将不同语言的 token 错误数混在一个分母中。候选模型通过完整 dev 复核后才称为最佳；普通 ASR 不设早停门槛。

双卡资源优先用于正式训练。面板评测使用已有 CPU 推理流程，单任务运行；评测队列落后时保留正在评测与最新待评 checkpoint，并明确列出未评步骤。最终完整 dev/test 在释放训练 GPU 后执行，不按小样本推测全量结果。

每次训练和评测都创建或接续 W&B，沿用 entity `1016097967-amphion`、project `open-audio-llm`；从 shell 配置读取凭据，启动后验证远端 step／指标。按来源、时长、人数、重叠和中英切换条件记录 loss、样本数、音频秒数、梯度、吞吐、输出触顶与评测结果。

## 8. 实施顺序与完成条件

1. 冻结已有源版本，完成会话／设备去重与官方 split 核对，发布六个真实会话来源的统一 SOT 派生数据。
2. 发布中英混合句 ASR 子集及新词级合成版本，记录实际可用规模、对齐失败率、上下文拒绝率和增强分布。
3. 验证新增转换中的文本完整性、speaker 一致性、合法边界、RIR 时间映射和 16k 预算；冻结训练配置、dev 面板及起点。它们是数据／实现检查，不安排额外试训。
4. 数据就绪后，在明确的切换点保存当前运行完整状态，启动一次新正式训练并拉起 W&B。本文没有执行停机或启动动作。
5. 按固定协议评测并交付最佳 checkpoint、完整数据血缘、W&B 链接和分桶结果。

不得在新合成或某个来源准备失败时，悄悄用旧合成补满权重并仍称其为本配方；应更新实际计划和版本说明。当前训练日志、权重和用户未提交改动均保留。
