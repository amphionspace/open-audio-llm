## 一、问题与评测集

- badcase：3 人同房间交替说话，声纹不知哪台设备录、混合音频是带降噪的手机麦克风。注册劣化、手机降噪、开场数数等信号模拟都复现不了。
- 对真实会议窗口做失败挖掘后，跟错人与三项强相关：目标被重叠 ≥30%（12% 对 0%）、目标说话 <10 秒（10% 对 0%）、注册相似度 <0.4（21% 对 0%）；谁先开口影响小。
- 据此发布评测集 `open-audio-llm/ts-asr-first-other@v3-20261105`（audio-data-contract #170、AmphionEval !117）：crowded / crowded-lowsim / control，9,030 条。跟错人 = 输出覆盖目标 <60% 且 >40% 不是目标，从 predictions 另算。
- SFT 侧加"别人先开口""注册换通道"两项增强（open-audio-llm #118，SFT 068）没有改善跟错人，所以改用 GRPO。

## 四、判读与决定

- CHiME-4（英文）的空输出从第 200 步起上升，与第六至八轮同一机制：挖掘只在第 0 步做，训练中门槛移进带噪英文时没有反推样本；在 v10 avg3 上重挖也挖不出这类正例。用户 11-06 定 CHiME-4 不作守门。
- 插值是线性取舍：25% 时 lowsim 收益归零（9.30%），CHiME-4 仍高于 v9 插值。
- 用户 11-06 接受警务单说与鼎桥场景漏识的小回退，"测一下对比10.28，没问题就发布"。客户录音在线上条件下好于 10.28，所以发布 v10 插值 50%。
- 包自检：包内 `serve.sh tsasr`（5 秒）重跑 v12 全量 12.87 对正式评测 12.88；客户热词 15.82 对 15.40；`client.py`、`infer.py` 各模式正常。

## 五、遗留

- 不带热词时的警务指令近音错误：线上每段只召回最多 50 条热词，漏召回时会落到这一档。下一轮（第十一轮，起点 v10 avg3，`tasks/24-grpo-v11-from-v10avg3`）要把警务术语纳入挖掘重点。
- 跟错人率还没有内置进 AmphionEval 的 ts-asr 评测器。
