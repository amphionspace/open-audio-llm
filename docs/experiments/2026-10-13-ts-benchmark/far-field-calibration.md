# 远场与房间响应：补充评测集与真实校准

状态：2026-10-14。评测集 `ts_asr_farfield@v1-20261014`（合成，1,680 条）、`ts_asr_nearfar@v1-20261014`（AliMeeting 真实近远场对照，1,248 条），都已登记并发布到 AmphionEval。三个模型的完整运行见 [baselines/README.md](baselines/README.md)。

## 结论

1. **最脆弱的情形是「目标远、别人近」。** 只有目标过房间响应（目标像坐在房间另一头，干扰人是干的）时，0923 版字错率 +36 个百分点，0926 版 +42，漏识分别到 17% 和 30%。反过来只有干扰人过房间响应时，目标不变差（−5 到 −2）。目标和干扰人过同一个房间响应、或各过不同响应，介于两者之间（+23 到 +31）。CocktailASR 趋势相同但漏识很少（3%），主要是转写了别人（17%）和字错率（+25）。
2. **注册和混合的近远场不一致会出问题，方向在真实数据上得到验证。** 注册是远场、混合是近场，两个自家模型字错率合成 +18 到 +20，真实 AliMeeting +22 到 +26；漏识合成 +13 到 +17，真实 +14 到 +24；两边显著，数量级一致。
3. **「近场注册、远场混合」（业务最接近的情形）合成和真实不一致。** 合成字错率 +28 到 +31，漏识 +12 到 +22；真实 AliMeeting 只有 +1 到 +3，漏识 0。原因不能确定，最可能的是自家模型训练见过 AliMeeting 远场（真实数据是同域的），而合成用的是实测房间响应，对模型是没见过的房间；Cocktail 的真实数据反而比合成更差（3 人以上窗口字错率 +70 对 +16）。所以合成的混响数值**不能当作业务的预测值**，它测的是对没见过的房间的鲁棒性。要预测业务，需要业务现场的远场录音（见 [plan.md](plan.md)）。
4. **干扰人数和重叠的方向一致。** 干扰人 2 个及以上比 1 个更差（字错率、转写了别人、漏识），合成评测集和真实 AliMeeting、AISHELL-4 同向，三个模型都是；重叠比例 0.6 以上最差也同向。唯一不一致的是目标缺席的误输出：合成里 1 个干扰人时更高，真实里随干扰人数增加（真实基线只有 2%–14%，已被训练域吸收，说明不了什么）。
5. **注册要不要远场不是主要因素。** 混合是远场时，近场注册相对远场注册（失配代价）三个模型都不显著。

## 评测集

`ts_asr_farfield`：基线 `panel-base` 与 v3 面板逐条相同，其他场景与它配对（同一批说话人、位置、干扰人）。房间响应用 SLR28 实测房间响应（`real` 池），保持干电平，所以只改变直达声与混响的比例。

| 场景 | 目标 | 干扰人 | 注册 |
| --- | --- | --- | --- |
| `rirtgt` | 过 RIR | 干 | 近场 |
| `rirint` | 干 | 过 RIR | 近场 |
| `rirsame` | 过同一个 RIR | 同一个 RIR | 近场 |
| `rirdiff` | 各过不同 RIR | 各过不同 RIR | 近场（也是「近场注册、远场混合」） |
| `mmfarfar` | 各过不同 RIR | 各过不同 RIR | 远场（过 RIR） |
| `mmfarnear` | 干 | 干 | 远场（过 RIR） |

`ts_asr_nearfar`：用 `ts_asr_real@v2` 的 AliMeeting 窗口（各 50 个，三档说话人数），同一窗口四种条件：注册取远场或说话人的头戴麦（同一条语句），混合取远场通道 0 或各头戴麦之和（电平对齐远场混合）。近场和远场录音的时间偏差不超过 0.12 秒。

## 限制

- AISHELL-4 没有近场录音，只能做干扰人数和重叠的协变量校准，不能做近远场对照。
- 「目标和干扰人各自房间响应」这组没有真实对应（真实录音里不知道每个人的响应），不能校准，只能当脆弱点的诊断。
- 真实的「近场混合」是各头戴麦相加，含相互串音，不是纯粹的干声；电平对齐了远场混合，只剩声学差异。
- 自家模型训练见过 AliMeeting 和 AISHELL-4 的训练集，真实窗口是同域的，结论 3 的解释有这个混淆。
