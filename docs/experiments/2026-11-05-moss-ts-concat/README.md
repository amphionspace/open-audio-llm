# 用说话人日志模型做目标说话人识别：MOSS 拼注册（2026-11-05）

**结论：不能替代我们的 TS-ASR。** 把注册音频拼在混合音频前，交给 MOSS-Transcribe-Diarize（开源说话人日志 + 转写模型）区分说话人，再取第一个说话人（S01）作为目标人。在 TS 评测全集上，它比 10.28 交付版（054 avg3）差得多：字错率约 4 倍，漏识约 11 倍。46 个场景组里只有 1 组它明显更好。

## 二、为什么不行

- **"S01 就是目标人"这条规则基本成立**：只有 1% 的样本里注册段主讲人不是 S01。改成"注册段里说话最多的人"，结果几乎不变（CER 53.9）。
- **真正的问题是认不出同一个人**：漏识样本里，目标人说的话 MOSS 大多转写对了，但给了一个新编号（S02、S03），没有认成注册的那个人。注册和混合音频的录音条件差得越多（混响、远近、电平），这种情况越严重。这和此前会议评测里"MOSS 会把同一个人拆成多个说话人"是同一个现象。
- **复读**：31 条陷入复读（如"我我我…"），一直输出到长度上限，已按实际输出计入分数。

**回答"理想的说话人日志能否替代 TS-ASR"**：理论上可以。只要它在拼接后的音频里始终把目标人和注册段归为同一人，取出这个人就是 TS 的答案。但这要求它在录音条件变化时仍能认出同一个人，而这正是 TS 模型专门训练的难点，也正是 MOSS 这次失败的地方。多目标拼接要求每个人的编号都对上，只会更难，所以暂不测试。

## 三、做法与口径

| 项 | 内容 |
|---|---|
| 输入 | 与我们的 TS 服务收到的相同（注册截取或补齐到 5 秒，后接混合音频），中间插 1 秒静音 |
| MOSS 推理 | 官方 vLLM（固定提交 68b4a1d5），服务端默认提示词，temperature 0，在模型自己的环境里以独立进程运行 |
| 取目标 | 注册结束后（≥ 5.5 秒）开始、编号为 S01 的片段 |
| 打分 | AmphionEval 当前打分（v3），两边逐条重算。10.28 当时发布的汇总用的是旧版（v1，CER 13.23），本文统一按 v3（13.07） |
| 发布 | 不是 MOSS 的官方用法，没有发布到团队共享的评测记录 |
