# 目标说话人（TS-ASR）修复方案

状态：**方案，未执行**。依据见 [分析](README.md)。数字标「提议」的是设计值，执行前需要确认；没有标的来自实测。

## 目标与原则

目标：降低业务场景（手机原始麦克风、办公室或户外、注册人不说话时周围有他人声音）下 TS-ASR 的三类问题：转写了别人、目标缺席时误输出、漏转写。

- 先用不训练的手段摸清能解决多少，再决定训练规模。
- 只设一轮训练，不做参数扫描；先静态核对数据契约、增强是否真的生效，再启动。
- 部署契约不变：注册 3 秒加混合音频，中间插入 `[SEP]`（服务端按固定 3 秒切分）。所以只改「取哪 3 秒」和「这 3 秒多脏」，不改长度。
- 业务反馈数据只用于评测，不进训练。

## 轨道 B：评测基础（先于训练）

1. **压力面板**：已完成，见 [目标说话人 ASR 评测集与基线](../2026-10-13-ts-benchmark/README.md)（`ts_asr_benchmark@v1-20261013`，AmphionEval `open-audio-llm/ts-asr-benchmark@20261013`）。训练验收门改用它的场景。
2. **业务批次累积**：向业务要更多反馈，至少 20–50 条，真实手机麦克风，注册条件多样，并且要有带逐字稿的正样本（含漏转写）。`business_feedback` 每批一个版本，评测集同步登记新版本。
3. **真实会议 TS**：未合并的远端分支 `origin/docs/ckpt34479-turn-taking-eval` 记录了 34479 的真实会议话轮结果，但清单没有进主线；训练前补一份可复现的清单，作为真实数据的保持项。

### 数据

保持阶段 3 里 TS 的总占比不变，只改 TS 内部构成，不动 ASR 回放、热词、警务的配比。

| 项 | 做法 | 对应证据 |
| --- | --- | --- |
| 注册音频取窗 | 在完整注册语句中随机取 3 秒，优先有声帧；一部分样本只含有限语音再补零 | 短注册、开头静音 |
| 注册音频增强 | 噪声、RIR、窄带、增益，独立作用于注册和混合音频，概率约 0.5（提议）；噪声和 RIR 用 Catalog 里的 DNS5 | 噪声、窄带 |

| 加入单人 | 加入 `train_1spk`（326,176 条） | 漏转写 |
| 负样本形态 | 增加单个干扰人、纯噪声或音乐、短片段（0.3–1 秒），目标均为空 | 单个干扰人误输出 18% |
| **噪声底** | 所有训练音频（混合和注册）加白噪声或粉红噪声底，−65 到 −35 dBFS；评测表明 −60 dBFS 就让缺席误输出翻倍，业务包都是带噪声底的真实录音。**优先级最高** | [噪声底](../2026-10-13-ts-benchmark/README.md)，v2 评测集的配对差值 |
| **非人声空目标** | 噪声、音乐、交通、近乎静音、极短片段（0.3–1 秒）作为输入，目标为空。底座在这些输入上几乎不输出文字，34479 输出 50–75%，说明是微调引入的退化 | [底座对照](../2026-10-13-ts-benchmark/README.md) |

## 风险与会推翻方案的事情

- 压力面板上的改善没有迁移到真实业务批次：说明合成劣化与真实场景不一致，需要更多真实数据，而不是继续堆合成增强。
- A4 验证门单独就能挡住大部分误输出：训练可缩小到注册音频稳健性。
- 本仓库管线无法直接加载 34479：需要先解决格式，或者回到并线路线。
- 34479 训练时的注册音频截取方式未知：若原训练已是随机起点，则「取窗随机」收益会小于预期。
