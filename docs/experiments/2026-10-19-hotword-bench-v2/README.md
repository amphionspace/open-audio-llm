# 热词评测集 v2：热词池检索列表（2026-10-19）

**结论：**

- **v2 按部署链路造列表。** 每个租户（约 200 句）一个热词池，池里是现网中文万词库加租户自己的词，共 9–13k 词，检索取 Top-50。数据 `hotword_bench@v2-20261019`，评测集 `open-audio-llm/hotword-bench@v2-20261019`。
- **只比 v1 难一点。** 7 个中文切片、两个模型：
  - 带正确词的主条件 `pool50` 和 v1 `k50` 比，ContextASR 以外，召回降 0.5–3.3 个点，B-CER 升 0–1.5 个点，误触发率升 1–5 个点。
  - 例外是 34479 在 AISHELL-2 上，三项都比 v1 略好。
  - 不带正确词时，误触发率多数反而略降。
  - 明显变难的只有 ContextASR，原因是同领域的租户词。`pool50` 误触发率：34479 从 64.6% 升到 79.7%，Qwen3-ASR-1.7B 从 29.0% 升到 35.2%。
- **原因：让模型出错的几乎只有读音相近的词。**
  - 两版每个列表都带同一批复核易混词：每句约 2.6 个，ContextASR 约 11 个。
  - 误触发的词里 66–98% 是这些易混词。
  - v2 换进来的约 46 个检索词，和所说内容字相同或部分音节相同，模型几乎都能排除。词库词的误触发每百句只有 0.2–13 次。
- **现网 RAG 返回的列表本身也主要是噪声。** 用存档的 326 条中文现网 Top-50 核对：
  - 每个列表里与所说内容完全同音的词只有 0.1 个；
  - 约 62% 的词与所说内容既不同字也不同音；
  - v2 规则检索出的列表反而比现网更"像"所说内容。
  - 所以，让列表更像现网，不会让评测明显变难。
- **两个模型的高低和 v1 一致。** 除 AISHELL 系列外，Qwen3-ASR-1.7B 召回更高，误触发率约为 34479 的 1/3–2/3。AISHELL-1、AISHELL-3 的测试文本大量出现在 AISHELL-2 训练转写里，34479 在这两个切片上的数字偏好（记录的 `labels.train_text_overlap` 标出了重叠条目）。
- **建议：**
  - 默认评测集改用 v2，评测成本不变；多了按租户词、词库词分开的误触发统计，ContextASR 也更接近企业领域词表。v1、v2 的数字不能混着比。
  - 主指标不变：`pool50` 的 B-CER、F1，`pool50_no_gold` 的误触发率。
  - 想再变难，需要读音相近词更密的真实租户词表，比如业务方的人名、产品名单；再加检索噪声没有用。

## 为什么改

v1 的 `k50` 由正确词、易混词和同 split 随机词凑满 50 个。部署时列表是 RAG 从约 1 万词的词库里检索出的 Top-50，而且每个租户有自己的词。v1 设计时假定随机词比现网列表容易，v2 按部署链路重造中文列表来检验这一点。结果见上：两者对模型的难度接近。

## 怎么造的

记录、音频、正确词和其余条件（`none`、`gold`、`official`、论文列表、英文全部条件）与 v1 逐条相同，只把中文切片的 `k50` / `k50_no_gold` 换成：

| 条件 | 列表内容 |
| --- | --- |
| `pool50`（主条件） | 正确词，加检索得分最高的其他池内词，共 50 个 |
| `pool50_no_gold` | 检索得分最高的 50 个非正确词 |

- **租户**：real_zh 按节目（subset）、ContextASR 按种子语料（seed_corpus）分组，其余切片整个 split 一组；组内按 sha256(id) 轮流切成每份约 200 句，共 159 个租户。
- **热词池**：
  - 现网中文万词库：发布包 `zh-10k.txt` 本机和 OBS 都没找到。用 audiollm-go 2026-09-13 召回复测中现网和候选 RAG 返回过的全部 Top-50 及目标词还原，共 8,841 词，约为原库的 88%，都是真实词库成员。
  - 加租户句子的正确词，以及每个正确词最多 3 个复核易混词。
- **检索**：
  - 查询用参考文本，所以列表与被测模型无关。
  - 打分沿用 open-audio-llm 两阶段评测的中文规则召回：子串 2.0 + 拼音滑窗 1.5 + 字重合 0.5 + 字 bigram Jaccard 0.3。
  - 去掉原来 score > 1.0 的截断，因为现网对非空词库总返回 50 个。
  - 参考文本里出现的词不作干扰词。
  - 抽 40 条与 open-audio-llm 原实现逐条对过，排序全部一致。
- **干扰词分类**（`metadata.distractor_kinds`）：
  - `confusable`：本句正确词的复核易混词；
  - `tenant`：同租户其他句子的词；
  - `base`：词库词。
  - 评测器按这三类分开统计误触发。
- **全量核查**：64,413 条记录全部检查过。
  - 列表都是 50 词；`pool50` 必含正确词，`pool50_no_gold` 不含。
  - 干扰词不出现在参考文本里，也没有重复。
  - 非中文切片的列表与 v1 相同。
- 每个池都存在 `hotword-pools.jsonl.gz`（第一行是词库）。代码在 audio-data-contract `scripts/hotword_bench/pool.py`、`recipe-v2.yaml`。

## 列表构成：现网、v1、v2 对照

下表统计每个列表平均有几个词属于各类，复核易混词除外。

| 列表 | 与所说内容完全同音 | 一半以上音节相同 | 只有同字 | 无关 |
| --- | ---: | ---: | ---: | ---: |
| 现网 RAG Top-50（326 条中文，当前线上版本） | 0.1 | 8.3 | 10.6 | 31.0 |
| v1 `k50_no_gold`（real_zh 前 800 条） | 0.1 | 2.5 | 3.5 | 41.4 |
| v2 `pool50_no_gold`（real_zh 前 800 条） | 1.3 | 45.1 | 1.1 | 0 |

- 两者都以同字、部分同音的词为主，例如说「路」时会出现南京路、建国路。差别在于 v2 几乎每个词都沾边，现网约 2/3 不沾边。
- 两版都另带每句约 2.6 个复核易混词，其中约 1.6 个完全同音。
- AISHELL1-NE、KeSpeech 的构成与 real_zh 相同。
- 统计方法：完全同音、音节相同都按不带声调的拼音算；"无关"是既不同字、也没有一半以上音节相同。
- 现网词偏向"听起来有点像"，不完全落在拼音分类里，所以"无关"一栏会高估现网列表的噪声程度。

## 局限

- **检索器与现网不同**：现网是音频双塔逐帧召回，v2 用参考文本做规则检索。现网 RAG 制品（encoder、adapter、文本向量）不在本机，没法直接重跑。上面的构成对照说明两者都以噪声为主，对模型难度影响很小。
- **正确词总能被检索到**：现网中文 Recall@50 约 83%（当前线上）到 90%（候选）。真实情况介于 `pool50` 和 `pool50_no_gold` 之间。
- **易混词偏密**：每个正确词的复核易混词都在池里，比真实租户池里的同音词多，这一点与 v1 相同。
- **词库不全**：只还原了约 88%，缺的是 500 条复测里从未被召回过的词。
- **英文没改**：cv-en 仍是 `k50`（正确词 + 随机词），GigaSpeech、LibriSpeech 用论文列表。
- **AISHELL 偏乐观**：AISHELL-1、AISHELL-3 的测试文本大量出现在 AISHELL-2 训练转写里（AISHELL1-NE 为 734/808 句），34479 在这两个切片上的结果偏好。

## 复现

```bash
# 数据（audio-data-contract，分支 feat/hotword-bench-pool；依赖 v1 已注册）
PYTHONPATH=src python scripts/hotword_bench/pool.py --source /workspace/data/datasets/hotword_bench/source/v2-20261019
python scripts/hotword_bench/eval_set.py --recipe scripts/hotword_bench/recipe-v2.yaml > eval-set.yaml

# 基线（服务起法同 v1 README；评测环境装 AmphionEval 分支 feat/hotword-bench-pool）
export AUDIO_DATA_CATALOG=/workspace/data/registry/catalog AUDIO_DATA_ROOTS_FILE=/workspace/data/registry/roots.json
ae open-audio-llm after-training --handoff baselines/<model>/handoff.json \
  --config baselines/<model>/after-training-hotword-bench.yaml
```
