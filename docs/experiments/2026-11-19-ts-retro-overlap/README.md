# TS-ASR 复盘与重叠语音白盒分析（2026-11-19）

**结论：**

- **过去两个月的大部分轮次只是在挪门槛。** 调负样本、None 偏置、难负样本 GRPO、KL、合并系数，都只是把误报换成漏报。
- **字错的大头不在误报。** 11.17 的中文 TS 字错里，"出不出字"（误报加整条漏识）只占 29%；71% 是目标在说话、模型也出了字，但重叠时转写错了。
- **这一块从 10.28 到 v98 没动过。** 10 个版本在重叠 ≥ 90% 样本上的转写错误率一直在 15.4–16.5%。同一句话单独录音时只错 3.1%，放进 TS 场景是 13.9%。
- **白盒定位。** 重叠时约三成错字在模型内部已经找不到正确答案。编码器按注册"挑人"挑得越清楚，转写错得越少：同等声学条件下字错率 8.5% 对 15.3%。第二节表里 10 个版本有 8 个的音频塔是跟着训练的，重叠转写照样没动。所以缺的不是解冻，而是一个直接针对"重叠时只留目标"的训练目标。
- **方向。** 先把守门拆成"出不出字"和"重叠转写"两项；训练上用"同一注册 + 干净原句"当老师，给重叠时的目标选择一个直接信号。

W&B：`AmphionASR-whitebox-overlap-retro-1117-v12`（https://wandb.ai/1016097967-amphion/open-audio-llm/runs/1deqonfe ，2,731 个汇总指标，已远端核验）。

口径：中文 TS-ASR 测试集 = `ts-asr-benchmark@v12-20261022`（26,750 条，部署推理栈 vLLM 0.18、贪心、5 秒注册）。11.06 = `amphionasr2-grpo-v10interp050`，11.17 = `whitebox-merge-v18a-es116inc`。本文的"字错"按 AmphionEval `scoring.tokens`（去标点）逐条对齐后统计，把 270 组合在一起算，合计字错率是 15.0%（11.17），和报告里分组加权的 12.80 口径不同，只用于看各类错误的占比和相对变化。

## 一、复盘：两个月里什么真的改变了能力

### 1. 时间线

| 阶段 | 主要做法 | 结果 |
|---|---|---|
| 10-12 ～ 10-20 | 回放业务 badcase；建 TS 测试集 v1 → v12；SFT 续训（011 → 033） | 非人声幻觉是微调引入的（底座 0%，0926 版 53–75%），加"非人声→空输出"样本后降到 0；短目标单独池修好 `solo-mid` 弃权；真实会议窗口把真实缺席误输出降约 1/3（代价是在场漏识 +1.5 点） |
| 10-20 ～ 11-06 | SFT 065/066 + GRPO v7–v10 | GRPO 收益三次复现；11.06 交付（12.88 / 371 / 369，跟错人 6.46% → 5.14%） |
| 11-07 | 白盒 + 免训练合并 | "两轮相加"是当时最好的模型；模型在 LLM 第 12 层已能分辨目标在不在场（AUC 0.997）；难负样本 GRPO、成对 margin、None 偏置都只是挪门槛；外部声纹（ECAPA）不比模型自身判断强 |
| 11-09 ～ 11-17 | 跨语言注册评测；西语（v69 → v96）；冻结音频塔；11.17 合并 | 西语普通识别 WER 86.6 → 5.4；音频塔更新是英文误报上升的来源，冻结后保住英文；11.17 = GRPO v18 骨干 + es116 增量，三项都不劣于 11.06 |
| 11-17 ～ 11-18 | 葡语（v97、v98） | 葡语普通识别 69.5 → 11.0、TS 80.0 → 33.7；中文 TS 误报逐轮上升 342 → 365 → 383，v98 未过守门 |

### 2. 真正改变了能力的做法 vs 只是挪门槛的做法

| 类别 | 做法 | 证据 |
|---|---|---|
| **改变了能力** | 非人声/静音的空目标样本 | 纯噪声、近静音出字 53–75% → 0（10-13、v9） |
| | 短目标单独池、真实会议窗口 | `solo-mid` CER 9.0 → 5.8；真实会议缺席 7.3 → 4.9（10-20） |
| | GRPO（跟错人场景） | first-other crowded 6.46% → 5.14% → 11.17 的 3.91% |
| | 新语种数据（西语、葡语） | 从不可用到 5.4 / 11.0 |
| | 免训练合并（任务向量相加、按模块换增量） | "两轮相加"、11.17 都由合并得到；冻结/替换音频塔增量压住英文误报 |
| | MTP 联合训练 | 接受长度 2.7–2.8，分数不变 |
| **只是挪门槛**（误报和漏识此消彼长） | 缺席样本比例 ×1.5 / ×3、目标缺席权重 | v87："只把误报换成漏报"（405 / 489） |
| | 难负样本 GRPO（v21–v25）、成对 margin（v66） | 落在"两轮相加 + None 偏置"的曲线上或下方 |
| | ` None` logit 偏置、探针门控、steering | 白盒 08、05、06 |
| | 冻结基座 KL、合并系数 0.5 / 0.75 / 1.25 | v85–v94；系数越大误报越高、漏识越低 |

SFT 原始模型从 v79 起的"误报 + 漏识"合计一直在 802–894 之间；交付版和候选合并版（两轮相加、es116、11.06、11.17、葡语候选、v98）在 699–790 之间。同时降低两项的只有两次：一是从低误报的 GRPO 骨干出发再加增量（11.17），二是 GRPO v27 avg3。

### 3. 被推翻或一直没被证实的重要结论（节选）

| 原结论 | 后来 |
|---|---|
| 西语 MTP 接受长度低是结构问题 | PR #164 之前 `--joint_mtp_lr` 从未生效，修好后 2.78 |

| 0926 版优于 0923 版 | 0926 缺席误输出平均高 8 点，业务分析都以它为对象 |

### 4. 工作方式上的问题

- **结论散落在配置注释里。** attempt 079–127 的 README 都只写"执行完成，质量未核实"，结论只在 `configs/train-*.yaml` 头部注释和包的 `model_info.json` 里，实验顶层 README 停在 10-22。
- **已证伪的方向被重复。** 合并系数扫描、缺席权重和 CV27 剂量点在已有结论后又跑过（11-15 起要求先白盒）。
- **评测口径漂移。** 同一个 0926 模型的 `abs-hard` 误输出在 v1 / v2 / v3 上分别是 41.7 / 51.7 / 47.5。
- **守门只看三个合计数，没把字错拆开。** 中文 TS 守门是"字错率 / 误报条数 / 漏识条数"。11-06 以后的轮次几乎都按误报条数取舍，下面第二节说明，字错的大头不在这里。

## 二、新拆分：中文 TS 字错的七成来自"目标在说、重叠时转写错"

### 1. 11.17 的字错构成

| 错误类型 | 字数 | 占全部字错 |
|---|---:|---:|
| 误报（目标没说话却出字） | 4,903 | 14.6% |
| 整条漏识（目标在说却输出空） | 4,919 | 14.6% |
| 目标在说、也出了字，但替换错 | 15,969 | 47.5% |
| 同上，漏字 | 5,320 | 15.8% |
| 同上，多字 | 2,516 | 7.5% |

"出不出字"类（前两行）合计 29%，过去的守门和大部分训练都在这一块；转写类（后三行）合计 71%。转写错出来的字里，只有 8.3% 是抄了干扰人的原话（随机对照 0.4%），多数是被干扰后认错。

按目标与干扰人重叠的程度分（目标在场、且出了字的样本，替换 + 漏字 + 多字）：

| 重叠比例 | 样本 | 转写错误率 | 占全部字错 |
|---|---:|---:|---:|
| 0 | 3,743 | 6.11% | 10.8% |
| < 0.3 | 368 | 9.81% | 5.2% |
| 0.3–0.6 | 770 | 9.12% | 5.1% |
| 0.6–0.9 | 3,515 | 10.29% | 25.2% |
| ≥ 0.9 | 4,554 | 15.64% | 39.2% |

重叠 ≥ 0.6 的样本贡献了全部字错的 64%。

### 2. 同一句话：单独说 vs 放进 TS 场景

v12 里有 11,760 条目标在场样本，目标原句来自 AISHELL-1/2/3、KeSpeech、MagicData 测试集，可以按句子 id 对上同一模型在普通识别测试集上的输出：

| 范围 | 样本 | 原句单独识别 | TS 场景 | 干扰带来的差 |
|---|---:|---:|---:|---:|
| 全部 | 11,760 | 3.10% | 13.86% | +10.76 |
| 无干扰人 | 2,580 | 2.18% | 6.44% | +4.26 |
| 1 个干扰人 | 4,106 | 3.63% | 8.21% | +4.57 |
| 2 个干扰人 | 4,370 | 2.79% | 17.09% | +14.30 |
| 3–4 个干扰人 | 704 | 3.4% | 34–37% | +30 ~ +33 |
| 重叠 ≥ 0.9 | 4,490 | 3.20% | 17.98% | +14.78 |

目标在场样本的字错里，约 78% 是干扰带来的（10.76 / 13.86）。把整条漏识去掉后，TS 场景是 11.48%，仍是单独识别的 3.7 倍。

## 三、白盒：重叠时目标的字丢在哪

对象：11.17。v12 全部 12,953 条目标在场样本，每条跑三遍前向，输入构造与 `runs/whitebox-20261107` 相同（ms-swift 模板、5 秒注册、音频塔全局注意力）：
1. 用模型自己的 vLLM 输出逐 token 核对。HF 贪心与 vLLM 一致 99.52%（214,068 / 215,095）。
2. 用参考文本逐字打分。看每个参考字在模型候选里排第几（排名不算标点），以及排第一的是不是干扰人说的字。
3. 混合段不动，把注册换成另一个人。比较编码器各层、LLM 各层在混合段上的表示变了多少，并按时间分成"只有目标在说""重叠""只有干扰人在说""静音"四段。

### 1. 错字是"差一点"还是"根本没有"

参考字在模型候选里不是第一名的那些位置：

| 范围 | 参考字排第 1 | 错的里面：排 2–5（差一点） | 排 20 以外（基本没有） | 排第一的是干扰人的字（随机对照） | 提前结束 |
|---|---:|---:|---:|---:|---:|
| 全部 | 89.4% | 60.4% | 21.8% | 9.6%（6.4%） | 0.1% |
| 重叠 0 | 93.0% | 76.5% | 9.0% | 0.4%（4.0%） | 0.1% |
| 重叠 0.6–0.9 | 89.9% | 59.7% | 23.6% | 12.2%（8.4%） | 0 |
| 重叠 ≥ 0.9 | 86.4% | 53.2% | 28.7% | 14.2%（6.5%） | 0.1% |
| 4 个干扰人 | 77.9% | 44.6% | 36.8% | 21.4%（7.1%） | 0.2% |

- 没有重叠时，错字九成以上是"差一点"，多为同音、近音。
- 重叠 ≥ 0.9 时，"基本没有"的比例升到 29%，是无重叠时的 3 倍。也就是说，约三成错字在模型内部已经找不到正确答案。
- 错成干扰人的字只比随机对照高 8 个点，不是主因。
- 提前结束几乎为 0，漏字不是"停得太早"。

### 2. 编码器有没有按注册来挑人

换注册后混合段表示的余弦（1 表示完全没变）：

| 时段 | 编码器第 12 层 | 编码器末层 | LLM 输入（音频投影后） | LLM 第 16 层 |
|---|---:|---:|---:|---:|
| 静音 | 0.941 | 0.896 | 0.851 | 0.756 |
| 只有目标在说 | 0.902 | 0.828 | 0.748 | 0.739 |
| 只有干扰人在说 | 0.873 | 0.815 | 0.712 | 0.705 |
| 重叠 | 0.811 | 0.717 | 0.530 | 0.709 |

- 编码器确实在用注册信息：同一段混合音频，换个注册，编码器从第 8 层起表示就明显不同，重叠时段变得最多。这和 11-07 报告的结论一致：编码器能把真注册和相似嗓音注册分开。
- 但"只有干扰人在说"的时段和"只有目标在说"的时段变化差不多。如果编码器只在增强或抑制目标，换成第三个人的注册时，干扰人时段本应基本不变。所以编码器对注册的利用是混在一起的，没有形成干净的"只留目标"。

### 3. 编码器挑得越清楚，转写错得越少

每条样本的"选择性"定义为：换注册时，重叠时段比只有干扰人的时段多变了多少。取重叠 ≥ 0.6、三段都有的 7,576 条，按干扰人数 × 干扰强度 × 重叠程度分层后比较：

| | 选择性最低的 1/4 | 选择性最高的 1/4 |
|---|---:|---:|
| 字错率（编码器末层） | 15.33% | 8.47% |
| 字错率（LLM 第 14 层） | 15.21% | 7.92% |
| 正确字排 20 名以外 | 4.13% | 1.76% |

做多因素回归（字错率对选择性、干扰强度、干扰人数、重叠比例、场景组）：
- 选择性每高 1 个标准差，字错率低 2.3 个点。
- 干扰强度每高 1 个标准差，字错率高 2.9 个点。
- 干扰人数每多 1 个标准差，字错率高 5.2 个点。

选择性的作用与声学条件同一量级，而且在编码器末层就已经出现。

**结论：** 重叠转写的瓶颈和"编码器按注册挑人挑得清不清楚"强相关，而且约三成错字是信息在模型内部已经找不到。音频塔并不是一直没训练过，但从来没有一个训练目标直接针对它：
- v95 之前，除卷积前端外，音频塔都和 LLM 用同一学习率、只跟着文本交叉熵一起更新。第二节表里的 SFT 轮次用的是 2e-6～3.55e-6，GRPO 用的是 1e-6；
- 11.17 的音频塔来自 GRPO v18。v95 起（v95–v98 与只训 MTP 的轮次）音频塔整个冻结，原因是它的更新抬高了英文 TS 误报；
- 第二节表里，除 SFT 116 和 v98 外，8 个版本的音频塔都在训练中更新过。这两个版本冻结了音频塔，但沿用的也是更早训练过的音频塔。10 个版本在重叠 ≥ 0.9 上的转写错误率都在 15.4–16.5%。所以单靠解冻、只用文本交叉熵，改变不了它。

**局限：**
- 这是相关分析，不是干预实验。比如目标与干扰人嗓音相近，会同时降低选择性、抬高错误率，这里没有单独控制（不过这本身也属于说话人表示的问题）。
- 余弦只反映"变了多少"，不反映"变得对不对"。

## 四、更本质的优化方向

### 1. 先改评测和守门（不用训练，立刻可做）

- 中文 TS 守门在"字错率 / 误报 / 漏识"之外，拆出两项：
  - "目标在场且出了字时的转写错误率"，按重叠 0 / 0.6–0.9 / ≥ 0.9 分开报，11.17 分别是 6.11 / 10.29 / 15.64；
  - "同句干扰代价"，即 TS 场景减去原句单独识别，11.17 是 +10.76。
- 理由：现在的守门只盯误报条数，过去一个月的取舍几乎都在误报和漏识之间互换。拆出来以后，"误报 +12 但重叠转写 −3 个点"这样的候选才能被正确评价。

### 2. 给"重叠时只留目标"一个直接的训练信号：用干净原句当老师

- 在线混音时，目标原句是已知的。同一个模型在这些原句上只有 3.1% 的字错。
- 训练时多跑一遍"同一注册 + 干净原句"作为老师，有两种用法：
  1. **输出层**：让学生（输入是混合段）在转写 token 上的分布贴近老师（KL）。它针对的是 53% 的"差一点"错字，信号比只用参考文本的交叉熵密得多。
  2. **编码器层**：在目标说话的时段，让学生编码器的表示贴近老师编码器（干净原句）的表示。它针对的是 29% 的"信息丢了"和第 3 节的选择性。
- 编码器层对齐需要重新解冻音频塔。v95 起冻结它，是因为它的更新抬高了英文误报，所以要同时保留普通识别上的 KL 和回放，并把英文 TS 误报（11.17 是 655）设为守门。
- 不建议的方向：
  - 继续调负样本比例、None 偏置或合并系数，这些只是挪门槛；
  - 接入外部声纹，11-07 白盒 10 已证明外部声纹提供的信息比模型自身少。

### 3. 注册质量（推理侧，只需评测）

- 下游选注册片段时，与本人的 ECAPA 相似度中位数是 0.84，我们固定取最早一句，只有 0.76。
- 注册长度对误报的影响已经测过（3–8 秒没有差别），对重叠转写的影响还没测。
- 可以只跑评测：用 10 秒注册、或挑质量最好的片段，看重叠 ≥ 0.9 的转写错误率。不用训练，结果能直接给下游用。

### 4. 若要验证方向 2，最小的一次实验

- 从 11.17 起训一轮，配方同 v96，开 MTP。设两组：
  - 实验组：解冻音频塔，加干净原句老师的 token 级 KL；
  - 对照组：只解冻音频塔，不加 KL，用来区分"解冻"本身的作用。按历史轮次（v95 之前音频塔一直在更新），预期对照组的重叠转写基本不变。但起点和数据都和那些轮次不同，所以仍要跑这一组。
- 要回答的未知项只有一个：直接的分离信号能否把重叠 ≥ 0.9 的转写错误率（15.64%）明显降下来，同时守住中文 TS 门槛（12.88 / 371 / 369）、英文 TS 误报和中文普通识别。
- 训练代码需要新增：在线混音输出干净原句，训练步里多做一次老师前向（TS 样本的计算量约翻倍）。
