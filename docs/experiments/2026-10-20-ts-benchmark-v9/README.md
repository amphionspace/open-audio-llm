# TS-ASR 评测集 v9：五个模型全量对比（2026-10-20）

状态：评测集 `open-audio-llm/ts-asr-benchmark@v9-20261020`（208 列，22,239 条）已合并（audio-data-contract #88、AmphionEval !44）并发布到 COS。五个模型都按 AmphionEval 标准流程（`ae open-audio-llm after-training`）全量运行，没有失败样本，W&B 远端已核对，运行已发布。

## 结论

1. **032 综合最好。** 自家 4 个版本里，032 在合成场景中「目标在场」的字错率最低。下面三组的字错率依次为 0923 / 0926 / avg3 / 032：
   - 有干扰人：51 / 47 / 24 / 20；
   - 注册音频劣化：31 / 33 / 23 / 21；
   - 目标和干扰人各自的房间响应：35 / 38 / 29 / 24。

   它的拒识和 avg3 一样好：目标缺席、别人在说话时，误输出依次是 29 / 35 / 4 / 5；完全没有说话声时是 65 / 63 / 0 / 0。avg3 用更多漏识换来了低误输出，多数组漏识 7–15%；032 的漏识是 4–11%，接近 0923 版。接话组和短句组例外，见第 4 条和结果表。
2. **线上的 0926 版（34479）拒识最差。**
   - 有人说话但目标缺席的各组：误输出 20–55%，几乎每组都比 0923 版高。
   - 没有说话声或只有歌声：误输出 63–78%。
   - 业务反馈的 34 条缺席样本：误输出 88%；avg3 和 032 都是 3%。
3. **开源的 CocktailASR-1 几乎不拒识，结论和 v3 时一样。**
   - 合成场景里有人说话、目标缺席：各组误输出 74–85%，单列最高 94%。
   - 真实对话的缺席窗口：误输出 77–100%。
   - 例外是 1.2–6 秒短片段：误输出只有 12–14%。
   - 没有说话声、只有音乐或噪声时，误输出只有 6–19%。
   - 它很少漏识（0–3%）。合成场景下，目标在场的字错率和 0923 版相当或略低。
   - 真实会议里它会把别人的话也转写进来，所以字错率高：AliMeeting 59–60%，AISHELL-4 36%；自家版本是 10–18%。
4. **新增的「目标说完、别人接话」组：032（14%）和 Cocktail（13%）字错率最低。**
   - 业务第 39 行的现象是：干扰人那句开头和目标相同，模型就输出干扰人的话。0923、0926、Cocktail 三个模型都复现了这个现象。和开头不同的对照列配对比较，「转写了别人」只在开头相同列出现的条数：0923 19 条对 6 条，0926 19 条对 6 条，Cocktail 11 条对 0 条。McNemar p 依次为 0.015、0.015、0.001。
   - avg3 和 032 基本不转写别人（0–3%），但会漏掉目标那句：avg3 漏 34–45%，032 漏 11–16%。漏识集中在 MagicData 目标句，原因见 PR #88 的校准说明。
5. **声音相近的人仍是自家版本最难的场景。**
   - 只有一个人在说时，注册人换成声音相近的人（`abs-hard-k1`），误输出 51 / 57 / 10 / 11 / 94；注册人是随机的人（`abs-rand-k1`），误输出 16 / 38 / 0 / 1 / 81。
   - 真实注册录音 realreg3 也一样：声音相近的干扰人（`realreg3-hard-neg`）误输出 24 / 62 / 3 / 6 / 94；随机干扰人（`realreg3-neg`）误输出 6 / 28 / 0 / 0 / 74。
6. **avg3 和 032 在 Emilia2 真实对话的缺席窗口上变差。** 误输出依次为 3 / 3 / 14 / 17：
   - 单人窗口：10 / 8 / 24 / 28；
   - 3 人以上窗口：0 / 2 / 11 / 13。

   AISHELL-4、MagicData 的缺席窗口不变或更好。Emilia2 用的是 MOSS 伪标签，也可能是标注漏了目标的话，要先抽样核对再下结论。
7. **业务回归组样本太少，只能看方向。** 缺席 34 条、在场 3 条。在场 3 条里：
   - 0923 和 Cocktail 三条都转写出了目标的话，字错率都是 8%。
   - 第 39 行那条（“现在我开始说话…”之后，干扰人接一句“我现在是在旁边干扰的人…”），0926、avg3、032 输出的都是干扰人那句。
   - avg3 另两条都输出为空，032 有一条为空。

看板说明：AmphionEval 看板上，avg3 显示为 `training-step0`，032 显示为 `training-step35000`。模型名取自 handoff 的 `training_run`，和它们在 v7 看板上的名字一致。

| 032 | ts-robust 032 ckpt35000，033 的续训起点 | 同上 |
| Cocktail | 小米 CocktailASR-1（开源，按参考音频转写指定说话人），`/workspace/model/Xiaomi-CocktailASR-1` | 官方推理：transformers，bf16，贪心；不支持 vLLM |

- 只测支持目标说话人转写的模型。Qwen3-ASR 这类不支持注册音频的模型不测。
- 输入：AmphionEval 统一的 3 秒注册 + 混合音频。Cocktail 的 worker 在 3 秒处拆开，再调用 `model(混合, 注册)`。官方做法是随机截 1–4 秒参考，这里固定取前 3 秒，与 v3 基线的做法相同。
- 分组数字是组内各列的平均，和看板一致。
- 「转写了别人」只看目标在场且有输出的样本：输出离某个干扰人的话比离目标的话更近，就记一次。判定规则同 audio-data-contract `scripts/ts_benchmark/analyze.py`。

## 怎么跑的

每个模型的配置在 [baselines/](baselines/) 下：

- `handoff.json`；
- `after-training.yaml`（评测）；
- 自家版本另有 `serve-tsasr.yaml`（TS-ASR 服务）。

本机 GPU 与其他人共用，所以服务的显存占比设为 0.22，每张卡只放一个服务。复现命令：

```bash
open-audio-llm serve --config baselines/<模型>/serve-tsasr.yaml        # Cocktail 不需要
ae open-audio-llm after-training --handoff baselines/<模型>/handoff.json \
  --config baselines/<模型>/after-training.yaml
ae --state-dir <output_root> publish <运行号>                            # 评测集发布后再发布运行
```

- 一致性核对：v9 里的 032 和它此前的两次运行逐列比较，同一模型、同一批样本。
  - 和 v7 全量运行（`run-20261020T024957Z-87215464`）共有 196 列，平均相差 0.2 个百分点。最大相差 2 个百分点，出现在 50 条的真实对话列里，只差一条样本，属于批推理的不确定性。
  - 和 v9 校准运行共有 10 个新列，最大相差 0.5 个百分点。
- 表格脚本在 [table.py](table.py)，它读取各次运行的 `summary.json` 和 `predictions.jsonl`。生成的逐列结果在 [results.json](results.json)。
