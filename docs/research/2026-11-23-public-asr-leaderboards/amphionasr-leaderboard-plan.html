AmphionASR 打榜：现状与建议

目标是借公开榜单提升 Amphion 的知名度。本页说明 AmphionASR 在公开榜单上的位置、我们真正领先的地方，以及建议的打法。

结论

  1. 不建议继续在 Hugging Face Open ASR Leaderboard 上投入训练。这个榜只测普通转写，以英文和欧洲语言为主，正好不是我们的强项。AmphionASR 在这些集上与底座 Qwen3-ASR 持平或略差；就算全部恢复到底座水平，英文也只排第 17 左右，没有宣传价值。
  2. 我们真正领先的是“目标说话人识别”。这个任务是只转写指定的人，其他人说话不写出来，公开榜单不测它。同一套约 5 万条中英测试上：中文字错率 12.8，开源同类最好的是 33.4，7 家商用 API 在 88 以上；目标不在场时，我们误把别人的话写出来的比例是中文 2.5%、英文 6.2%，对方在 50%–98%。
  3. 建议换一种打法：开源 AmphionASR 权重，发布 Amphion 的目标说话人识别评测集和排行榜，配一份技术报告。Open ASR Leaderboard 只在发布后如实提交一次，作为参考，不追名次。

需要决定：是否同意这条路线，以及由谁负责技术报告和对外发布。权重可以公开，负责人已确认。

为什么上不去

AmphionASR 是在 Qwen3-ASR 上为业务能力微调的，训练只用了中、英、西三种语言。微调后其他语言退化了，英文也比底座略差：训练标注逐字保留口语重复，模型照学了。

已经试过的

做了 3 组恢复训练和对照。多语种能部分恢复（11.18 → 8.37），但会让英文目标说话人识别多出误报、中英夹杂识别变差，过不了交付门槛。英文要换训练目标才可能回到底座水平。即使全部做到，也只是和底座持平，所以已停止。

我们领先的地方：目标说话人识别

场景是会议、多人对话、旁边有人说话或放音乐的时候，只转写指定那个人。用户先录 5 秒注册音，模型据此识别是谁。测试集共 49,771 条（中文 26,750 条约 75 小时，英文 23,021 条约 64 小时），包括合成场景，以及 AliMeeting、AISHELL-4、AMI、NOTSOFAR-1 等真实会议录音。所有模型用同一批样本、同一套打分逐条对比。

商用 API 都没有“只转写指定的人”的接口，只能把混合音频整段转写，别人的话全算作错误，所以错误率会超过 100。正式发布时需要补上“说话人分离 + 声纹匹配 + 识别”这类流水线做法作为基线，否则对比会被认为不公平。CocktailASR 是这次唯一测到的同类开源模型。

建议方案

思路是让我们的强项能被公开衡量：由 Amphion 定义这个赛道并开放评测，比在别人的普通转写榜上排第 17 更能建立影响力。

  1. 第 1 周

    整理可公开的评测集，补齐基线

    • 从现有测试集里挑出能公开的部分：真实会议录音和公开朗读语料合成的场景；去掉业务反馈里的真实注册录音等客户数据；逐一核对来源语料的许可，不能再分发的只发生成脚本或剔除。
    • 补“说话人分离 + 声纹匹配 + 识别”的流水线基线（例如 pyannote + Qwen3-ASR），和已测的 7 家 API、CocktailASR 放在一起。
  2. 第 2 周

    开源模型与排行榜

    • 在 Hugging Face 发布 AmphionASR 权重、模型卡和推理代码，并核对 transformers 版与我们 vLLM 部署版的结果一致。
    • 发布评测集和排行榜页面（Hugging Face Space），评测代码用已有的 AmphionEval，所有模型的逐条预测一并公开，方便第三方复现。
  3. 第 3 周

    技术报告与发布

    • arXiv 技术报告：方法、评测集、对比结果。英文和多语种比底座弱、AISHELL-1 文本重合这些情况都如实写，并给出去重后的数字。
    • Open ASR Leaderboard：按真实口径提交一次，作为报告里的参考项。

时间为预估，前提是有一位同事负责报告写作和对外发布。

已经具备的

  • 中英目标说话人识别测试集（约 139 小时）和 AmphionEval 评测代码已有
  • 7 家商用 API 和小米 CocktailASR 在全集上的结果、逐条预测已有
  • 与 Open ASR Leaderboard 同口径的评测，可在提交前预估名次已有
  • 公开测试集去重工具；已修复 FLEURS 中文训练文本里不读出来的英文括注已有
  • 公开版评测集裁剪与许可核对、流水线基线、Hugging Face 发布包、排行榜页面、技术报告待做

风险

  • 自建自评的公信力：评测集、评测代码和全部模型的预测都公开，基线按各家官方推荐的方式调用。
  • 对比公平性：商用 API 没有指定说话人的功能，直接比会被质疑，所以要加流水线基线，并单列“目标单独说话”的对照组；那一组里我们英文并不领先，照实展示。
  • 来源许可：部分会议和噪声语料可能限制再分发，能公开的范围要核对后才能确定。
