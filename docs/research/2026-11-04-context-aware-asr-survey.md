# Context-aware ASR 调研：方法与数据（2026-11-04）

**结论：**

- **主流做法已经收敛：把上下文当文本 token 放进 Speech LLM 的 prompt，再专门做一轮"带上下文的 SFT"。** Seed-ASR、Qwen3-ASR、Qwen-Audio-3.0-ASR 都是这条路，不再加专门的偏置网络。外挂偏置（WFST、CLAS、TCPGen）只适合热词列表，管不了"看懂语境再选字"。
- **难点不在"能不能用上下文"，而在"上下文是错的、无关的时候不被带偏"。** 实际部署时，历史文本是模型自己转出来的，会有错；只用正确历史训练，上线就会传播错误。Whisper 带上一段文本解码，在 Earnings22 上 WER 能涨 500 个百分点以上。所有新工作都在专门处理这件事：用模型转写的历史训练、随机丢掉上下文、造冲突或无关的历史、用 DPO/RL 惩罚误改。
- **会话维度的上下文分四种，难度和收益都不同：** ① 显式材料（热词、参会人、领域、幻灯片）；② 本会话已识别的文本；③ 历史音频本身；④ 同一段话里说话人自己的说明（本项目 `context_correction_zh` 已在测）。②是这次要做的核心，①已有热词能力，③是 2026 年的新方向，收益明确但成本更高。
- **数据没有现成的中文会话级训练集。** 公开集多是评测集（ContextASR-Bench、MM-ContextASR Bench），或者规模小（MLC-SLM 约 1.5k 小时、11 种语言）。可行的造法有两种，业界两种都用：真实长录音按时间顺序恢复成会话；LLM 写含同音实体的对话，再用 TTS 合成。
- **建议的下一步（本次不实施）：** 先做评测，再造训练数据。先建一个中文会话级评测集，按"无关、隐含、显式、被纠正、重复错误"五种历史分场景，指标看实体召回和误改率，CER 只做守门。这需要先跟用户确认产品场景（见文末待确认）。

## 1. 问题定义：哪些"上下文"

| 类别 | 例子 | 推理时从哪来 | 主要风险 |
| --- | --- | --- | --- |
| 显式材料 | 热词表、参会人名单、领域标签、幻灯片 OCR | 用户或业务系统提供 | 列表太长，或干扰词写进输出（误触发） |
| 会话文本历史 | 本会话前几句的识别结果；对话助手的回复 | 模型自己的输出，或对话系统 | 历史有错，错误往后传播；无关历史带偏话题 |
| 会话音频历史 | 前几句的原始音频 | 缓存 | 计算和显存成本高；流式延迟 |
| 段内自我说明 | "灰是灰色的灰""不是光辉的辉" | 当前音频本身 | 听清了却不用（本项目实测纠正率约 8%） |
| 未来上下文 | 后一句话 | 只有离线场景有，需要两遍解码 | 不能流式 |
| 长期记忆 | 用户改过的字幕、租户词库 | 编辑记录 | 隐私、过时 |

## 2. 方法谱系

| 方法 | 代表工作 | 怎么做 | 已报告效果 | 适用 |
| --- | --- | --- | --- | --- |
| **外挂偏置** | WFST shallow fusion、CLAS、TCPGen | 偏置列表编译成 FST 在解码时加分，或编码成向量给模型做注意力 | TCPGen 可处理 5,000 个偏置词加干扰词 | 只适合热词，不理解语义 |
| **文本上下文 + Context SFT** | Seed-ASR（2407.04675）| 用 <上下文, 语音, 文本> 三元组按一定比例混入普通 ASR 数据做 SFT；上下文由内部 LLM 按转写生成，作者发现比直接用长音频前文效果好 | 对话上下文集的严格召回（人名）：去掉 context SFT 从 80.63 降到 61.26 | 主路线 |
| | Qwen3-ASR（2601.21337）| 上下文放 system prompt，当背景知识，不听从其中的指令（防指令注入）；报告没写数据构造和评测 | 无公开数字 | 我们的底座，已有接口 |
| | Qwen-Audio-3.0-ASR（2609.07549）| 热词分 P0/P1 两级；同会话最近识别文本做"滚动上下文缓存"。真实数据按音频 ID 恢复会话顺序，只用前文，不经 LLM 改写；合成数据给同音实体配正确、冲突、带噪、空四种历史；RL 里加上下文实体命中奖励，误插入扣分 | 热词数字有；会话历史只有定性例子（张桂生→张贵生） | 最接近我们要做的 |
| **抗幻觉解码** | Seed-ASR joint beam search | 把有上下文和无上下文的概率加权合起来；先用无上下文分数剪掉声学上不可能的 token | 严格召回 65.45 → 80.63（对比无上下文解码），作者称剪枝对抑制幻觉很关键 | 推理侧可加，vLLM 需改解码 |
| **历史检索/挑选** | MARS（2508.01166，AAAI）| 不用固定窗口或全历史，按声学和文本相似度检索一段最相关的历史；历史用的是 Whisper 转写结果 | MLC-SLM dev MER 12.75 → 8.96；1.5k 小时训练超过用 179k 小时的系统 | 长会话 |
| | CLAR（2603.25460）、Apple 拼音检索（2409.15353）| 先从大词库里检索候选实体（双塔或按读音），只把少量候选放进 prompt | CER、B-WER 低于强基线 | 词库很大的场景 |
| **双向上下文 + 两遍解码** | NTU（2506.13396，MLC-SLM）| 前后各一句放 prompt；训练时 50% 概率对上下文挖掉 0–25% 字符，模拟识别错误；推理先单句解码，再带邻句结果重解 | MER 14.87 → 13.56；用正确上下文上限 13.16 | 离线转写 |
| **训练抗暴露偏差** | 2603.24034（2026-03）| 用 Whisper 转写当训练历史；context dropout p=0.5；挑 WER>20% 的样本做 DPO（正例参考文本，负例模型输出） | TED-LIUM 3：无历史 7.89，用正确历史训 5.59，用转写历史训 5.47，加 DPO 5.17；换成无关历史时 SFT 涨 2.46 点，DPO 只涨 0.46 点 | 任何用会话历史的方案都需要 |
| **多模态历史** | MM-ContextASR（2609.19765，NPU 等）| 历史里放用户的原始语音和助手的文本回复，不只放转写；只对当前句算 loss | 实体召回：语音+文本 87.84%，纯文本 86.48%（Qwen3-Omni）；"助手一直写错"场景语音+文本领先 5.2 点；未训练的模型在该场景比不给上下文还差 | 对话助手、方言、目标说话人 |
| **长音频一次解码** | ParaASR（2607.29279）| 32K 上下文，一次转写最长 30 分钟；训练数据把相邻片段拼接，再由 LLM 通读整场统一反复出现的术语和实体 | 长音频平均错误率 3.70，Qwen3-ASR-1.7B 为 4.20；没有专门报跨段一致性 | 离线长录音 |
| **后处理纠错** | ChFT / Chain of Correction（2409.07790、2504.01519）| ASR 出全文后，LLM 带全文上下文逐段纠错，输出"错→对"对，不重写全文以减少幻觉 | 优于基线 | 不改 ASR 模型时可用；看不到音频，同音字靠猜 |
| **少样本说话人适配** | Phi-4-MM ICL（2505.14887）| prompt 里放同一说话人的若干条音频-文本示例 | 12 条（约 50 秒）相对 WER 降 19.7% | 口音、方言 |
| 多模态材料 | MaLa-ASR、VAPO、SlideSpeech | 幻灯片关键词或幻灯片图像作上下文 | MaLa-ASR B-WER 相对降约 45% | 讲座、会议 |

### 共性经验

1. **只对当前句算 loss，历史和指令都 mask 掉。**（MM-ContextASR 明确写了；其他工作的做法与此一致。）
2. **训练历史必须和推理时同分布：** 用模型自己的转写，或人为加错，不能只用参考文本。上下文 dropout 让模型在没有或不信任上下文时退回纯声学。
3. **必须专门造"反例"上下文：** 无关、冲突、错误历史，否则模型学会"照抄上下文"。Qwen-Audio-3.0、MM-ContextASR 都这么做。
4. **上下文要短而准：** 全历史成本高、噪声多；检索一段相关历史效果反而更好（MARS）。
5. **CER 不能当主指标：** 上下文带来的收益集中在少量实体字上，总 CER 变化很小，要看实体召回和误改率。

## 3. 数据

### 3.1 训练数据怎么造

| 造法 | 谁在用 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 真实长录音按时间恢复会话，前文用模型转写 | Qwen-Audio-3.0、MARS、MLC-SLM 各队 | 分布真实 | 大多数句子不依赖上下文，有效样本稀少 |
| LLM 生成上下文文本（按转写反推一段相关背景） | Seed-ASR | 可控、量大 | 上下文过于"贴题"，和真实历史不同 |
| LLM 写含同音实体的对话 + TTS 合成，配多种历史 | MM-ContextASR（87 万例，17.5 万实体）、ContextASR-Bench、本项目 `context_correction_zh` | 针对性强，能造反例 | TTS 音色、口语化不足；需音频质检 |
| 相邻片段拼接长音频 + LLM 通读统一实体 | ParaASR（5 万小时伪标签） | 训练跨段一致性 | 依赖多系统 ROVER 伪标签质量 |
| 用户编辑历史 | Seed-ASR 产品演示 | 真实需求 | 需要产品数据 |

## 4. 评测怎么设计

- **按历史类型分场景对照**（取自 MM-ContextASR）：同一当前句，分别配 无关 / 隐含（同话题无目标词）/ 显式（历史里有正确实体）/ 被纠正（助手或用户纠正过）/ 重复错误（历史一直写错）五种历史，外加不给历史。
- **两组主指标**：实体召回（显式、被纠正场景要涨），误改率（无关、重复错误场景不能比不给历史差）。CER 只做守门。
- **历史来源分开测**：参考文本历史（上限）与模型转写历史（真实），两者的差距就是暴露偏差的大小。
- **会话内一致性**：同一实体在会话里多次出现时，写法是否一致（`context_correction_zh` 的"同名一致性"子类型可沿用）。

## 5. 与本项目的关系

| 已有 | 现状 |
| --- | --- |
| 底座 Qwen3-ASR system prompt 上下文 | 接口在，能接热词和任意文本 |
| 热词评测 v3 | 34479 人名召回最弱，给列表后同音人名反而写错 |
| 段内纠偏评测 `context_correction_zh@v1-20261018` | 纠正率约 8%，问题是"听清了但没用上"；生成器可复用来造训练数据 |
| 会话级历史 | **没有评测，也没有训练数据** |

段内纠偏与会话历史本质上是同一件事：模型要按上下文改选同音字。可以共用一套生成器和打分逻辑，只是上下文从"同一段音频里"移到"prompt 里的历史"。

## 6. 待确认（影响方案选择）

1. **产品场景**：会议转写、客服、对话助手，还是长音频离线转写？决定历史里有没有助手回复，是否需要音频历史。
2. **流式还是离线**：离线可以用双向上下文和两遍解码，流式只能用前文。
3. **会话上下文由谁维护**：服务端自动缓存最近识别文本（Qwen-Audio-3.0 的做法），还是调用方每次传入？这会改部署接口。
